# 提交材料的分级验收说明

本项目按大学课程设计的工作量验收：交付可运行的记忆方案、针对缺陷的测试、真实任务对照及结论报告。验收通过不要求通用编程 Agent 解出全部 30 个任务，也不以统计显著提升作为必要条件。

## 基础验收：方案能运行，改动有验证

在仓库根目录按 `submission/README.md` 安装依赖后执行：

```sh
node submission/run-local.mjs
node submission/check-regressions.mjs
python3 submission/validate.py
```

- 实现、类型检查和现有测试通过；同仓库的分支、工作树、任务记忆能按作用域共存和召回。
- 新增边界测试能复现旧版缺陷，并验证当前实现已修复。运行旧版时出现预期的断言失败，属于缺陷复现成功。
- 保存的三组召回结果能够独立复算，候选池内改善与池外漏召回都有逐例记录。

以上检查不调用付费模型。测试数量与数值结论以最终报告及保存证据为准。

## 效果展示：分层报告实际进展

| 层次 | 展示内容 | 判断方式 |
|---|---|---|
| 记忆模块 | 正确作用域召回、污染、漏召回和上下文大小 | 固定输入、真实写入与 SQLite 召回 |
| 目标修复 | 编程任务的目标缺陷是否修复 | 指定修复测试全部通过，另报回归情况 |
| 部分完成 | 有多少目标测试得到修复 | 每题修复比例；所有任务等权汇总 |
| 完整任务 | 修复是否同时保持已有行为 | 修复测试与回归测试全部通过 |

真实任务对照固定为 MiniMax-M3、30 题、两组各一次、统一 160 步和 30 分钟。失败任务、空提交和负向差异一并保留。新增的分层指标属于执行开始后补充的描述性分析，其时间与定义记录在 `MemoryCore/benchmarks/agent-e2e/reporting-rubric.json` 和 `submission/evidence/agent-e2e/reporting-amendment.json`。

## 提交完成条件

代码和测试可获取；30 组对照完整、60 次结果可复核；PDF 与原始结果一致且排版清楚。报告根据实际数据说明哪些工程问题已解决、是否观察到编程任务收益，以及仍存在的限制。少量任务差异用于小规模验证，不扩大为稳定的通用能力结论。
