\begin{abstract}
Long-running programming agents must preserve decisions while avoiding constraints that were renamed, corrected, reverted, deleted, or made invalid by a new branch or environment. Static retrieval can surface obsolete statements; deleting them discards provenance. We study a narrower question above an existing memory engine: how can a bounded lifecycle sidecar propose policy updates from feedback while preventing a retrieval proxy from promoting a worse answer policy?

We implement correction-linked predecessor--successor redirection, fixed-cost fallback, protocol-versioned policy search, simple temporal baselines, single-factor ablations, proxy-alignment diagnostics, and text-only correction detection in MemoryCore. The public experiments use Memora, MemOps, and LongMemEval-V2 as method-validation substrates rather than evidence about private programming traffic. On a frozen 50-question panel conditioned on obsolete \base exposure, fixed-budget \vone raises answer FAMA by 8.09 points (95\% persona-cluster CI: 5.17--12.59). A new 200-question census that is not conditioned on \base failure finds a smaller full-population gain of 1.42 points (CI: $-0.005$--3.08 points), but a confirmed 2.96-point gain on 92 forgetting-bearing questions and a remembering-MPA harm signal. Thus \vone is a conditional incumbent, not a universal default.

A proxy-selected \vtwo policy improves direct retrieval but loses 4.08 FAA points and uses 37.5\% more context than \vone on the conditioned panel. On the broad panel, none of four simple baselines, six isolated \vtwo factors, or combined \vtwo passes the frozen promotion gate. A stance-aware proxy raises Kendall's $\tau_b$ with answer FAMA only from 0.529 to 0.538. A text-only detector identifies invalidating sessions at 97.89\% precision and 79.64\% recall on persona-disjoint test histories, yet predecessor-link precision is only 20.05\%; this blocks an end-to-end correction-construction claim. Separately, evidence-preserving compression reduces injected tokens by 20.84\% on a checksum-frozen LongMemEval-V2 test while direct answer-atom support is unchanged, but no answer-level noninferiority is established.

Across eighteen directions, the durable result is a separation of proposal, promotion, and evidence scope: cheap feedback may propose a policy, downstream answers and cost must promote it, and uncertain correction links must abstain. Exact operational fallback is necessary but not semantic safety. The resulting code and adapters are portable to programming sessions, while repository-, branch-, commit-, and environment-scoped validity remains future work.
\end{abstract}

\section{Introduction}

Interactive software tasks evolve. A user can replace REST with GraphQL, rename an interface, invalidate a test expectation, revert a design, switch branches, or change the toolchain. A memory system that retrieves both an old and a current constraint can confidently reintroduce a rejected decision. Lexical and embedding relevance do not imply current validity. Permanently deleting history is also undesirable: provenance is lost, historical questions become harder, and the correction that explains current state may itself be inaccessible.

Long-term memory systems address hierarchy, extraction, consolidation, graph structure, and context management~\cite{packer2023memgpt,xu2025amem,chhikara2025mem0,rasmussen2025zep}. Benchmarks reveal failures in temporal reasoning, updating, and selective forgetting~\cite{maharana2024locomo,wu2024longmemeval,hu2026memoryagentbench}. Memora explicitly separates required memory from invalidated memory through Memory Presence Accuracy (MPA), Forgetting Absence Accuracy (FAA), and Forgetting-Aware Memory Accuracy (FAMA)~\cite{uddin2026memora}. MEMPROBE further argues that task completion and the recoverable state retained by memory are distinct capabilities~\cite{ma2026memprobe}.

This paper studies lifecycle control above MemoryCore, an open-source hierarchical memory service with conversation retrieval, atomic memories, scenes, profiles, HTTP access, SQLite FTS5, and vector retrieval~\cite{memorycore2026}. We do not retrain the extractor or replace the base index. Instead, a bounded sidecar records correction relations, transforms a fixed candidate list, and returns the exact base call on disablement or failure.

The central engineering risk is optimization by an incomplete proxy. A direct audit may show more current evidence and less obsolete evidence, while the generated answer becomes worse because context wording, entity anchors, extra slots, or decoder behavior changes. We therefore separate a \emph{candidate proposer} from a \emph{promotion gate}. The proposer may use cheap feedback; promotion requires frozen downstream quality, forgetting, cost, uncertainty, and integrity checks.

Our contributions are:
\begin{itemize}
  \item a correction-linked, fixed-budget lifecycle sidecar with bounded traversal, capacity, latency, switch-off, and whole-call \base fallback;
  \item a proposal--promotion protocol that rejects a direct-proxy winner after answer generation, and distinguishes quality promotion from efficiency promotion;
  \item a broad 200-question, 13-arm answer experiment with strong simple baselines and single-factor ablations, using MiniMax-M3 and DeepSeek-V4-Flash in a crossed no-self-judgment design;
  \item an eighteen-direction research ledger that retains negative results in shielding, routing, state projection, transition memory, procedure memory, evidence expansion, structured refutation, proxy design, and automatic linking;
  \item a text-only, persona-disjoint correction-construction audit showing that event detection transfers but predecessor linking does not;
  \item a separate evidence-preserving compression result and an explicit portability boundary for repository-, branch-, commit-, worktree-, and environment-scoped programming memory.
\end{itemize}

The main conclusion is deliberately bounded. Correction-linked management is useful when obsolete memory is present and the relation is known. The evidence does not justify enabling \vone on all traffic, does not validate private programming tasks, and does not solve end-to-end correction linking.

\section{Related Work and Research Position}

\paragraph{Long-term agent memory.}
MemGPT treats context management like a virtual-memory hierarchy~\cite{packer2023memgpt}. Mem0 extracts and consolidates persistent information, while A-MEM builds an evolving linked note network~\cite{chhikara2025mem0,xu2025amem}. Zep and its open-source Graphiti engine attach validity windows and provenance to evolving facts~\cite{rasmussen2025zep,graphiti2026}. Our mechanism is narrower: it augments, rather than replaces, an existing retriever and constrains every query-time action.

\paragraph{Evaluation beyond recall.}
LoCoMo and LongMemEval expose long-session temporal and update failures~\cite{maharana2024locomo,wu2024longmemeval}. MemoryAgentBench identifies accurate retrieval, test-time learning, long-range understanding, and selective forgetting as separate competencies~\cite{hu2026memoryagentbench}. Memora evaluates remembering, reasoning, and recommending over weeks to months and penalizes invalid-memory reuse~\cite{uddin2026memora}. MEMPROBE directly audits the retained memory artifact and reports that assistance can saturate while state recovery remains moderate~\cite{ma2026memprobe}. These works motivate our separation of direct memory evidence from answer-level use.

\paragraph{Feedback and self-optimization.}
Reflexion updates agent behavior with verbal feedback~\cite{shinn2023reflexion}. Memory-R1 learns add/update/delete/no-op memory operations, SelfMem refines memory strategy from environmental feedback, and DeferMem learns query-time evidence selection~\cite{yan2025memoryr1,yang2026selfmem,yin2026defermem}. We do not reproduce their training procedures. Our focus is a reviewable, bounded policy space and an incumbent-preserving promotion protocol for an existing store.

\paragraph{Memory for coding agents.}
SWE-MeM lets an agent decide when and how to compress long software-engineering trajectories and jointly optimizes memory with issue resolution~\cite{gao2026swemem}. Structurally aligned subtask memory reports that monolithic instance memory suffers from a granularity mismatch~\cite{shen2026subtaskmemory}. ToM-SWE maintains persistent user goals and constraints across stateful software-engineering interactions~\cite{zhou2026tomswe}. These studies demonstrate the relevance of memory to coding agents, but they do not remove our public-data limitation: Memora has no repository, branch, commit, worktree, or toolchain labels. We therefore present programming transfer as a scoped adapter design, not an empirical result.

\section{Problem Formulation}

Let the unchanged base retriever return a ranked pool
\[
B(q)=(m_1,\ldots,m_K),
\]
and let its injected prefix be $B_k(q)$. A lifecycle event is
\[
e=(t_e,\kappa_e,c_e,V_e^{-},S_e,s_e),
\]
where $t_e$ is sequence, $\kappa_e\in\{\text{update},\text{delete}\}$ is kind, $c_e$ is confidence, $V_e^{-}$ contains invalidated values, $S_e$ contains successor memory identifiers, and $s_e$ records provenance. A predecessor memory receives an edge to $S_e$ when it predates the event and contains an invalidated value.

A policy $\pi_\theta$ maps $B(q)$ and the bounded lifecycle ledger to an injected list. The policy must satisfy capacity, latency, result-count, and integrity bounds. If the sidecar is disabled, malformed, cyclic, over capacity, or timed out, the entire call returns $B_k(q)$ rather than a partial transformation.

We distinguish three objectives:
\begin{enumerate}
  \item \textbf{quality}: improve downstream answers without violating forgetting safety or cost;
  \item \textbf{efficiency}: preserve a frozen quality invariant while reducing context cost;
  \item \textbf{construction}: infer lifecycle events and predecessor links without oracle operation metadata.
\end{enumerate}
Changing the objective after scoring is forbidden. In particular, a candidate frozen as a quality improvement cannot be retroactively promoted because it saved tokens.

\section{Lifecycle Policies and Promotion}

\subsection{Base and fixed-budget V1}

\base is the unmodified MemoryCore L0 retrieval and injection path. The research incumbent \vone follows the latest eligible correction edge for an obsolete base candidate, removes duplicate leaves, and refills from the same base pool. Its fixed parameters are
\[
\tau=0.85,\qquad H=1,\qquad E=64,\qquad k=5,\qquad T=10\text{ ms},
\]
for confidence, hop count, expansion capacity, output count, and sidecar wall time. The ledger may link a predecessor directly to the latest eligible correction, so one query-time hop can represent a longer update history.

The Memora implementation constructs V1 edges from released write-time operation fields. These fields do not contain evaluation answers, but they do make the management experiment quasi-oracle with respect to event type and invalidated value. Section~\ref{sec:d18} separately evaluates a text-only constructor.

\subsection{Contextual V2}

The \vtwo candidate space varies confidence $\tau\in\{.85,.91,.96\}$, hops $H\in\{1,2\}$, redirect-conditioned extra slots $s\in\{0,1,2\}$, and historical-aggregate protection $p\in\{0,1\}$. The 36-policy proposer optimizes a direct forgetting-aware proxy on weekly/monthly feedback and selects $\tau=.96$, $H=2$, $s=2$, and $p=1$. Capacity remains 64 and time remains 10 ms. \vtwo is a proposal, not an automatic deployment choice.

\subsection{Tiered promotion}

For incumbent $\theta_I$, challenger $\theta_C$, and frozen checks $g_1,\ldots,g_J$, the research policy is
\[
\theta^*=\begin{cases}
\theta_C,&\bigwedge_{j=1}^{J}g_j=1,\\
\theta_I,&\text{otherwise.}
\end{cases}
\]
Cheap feasibility checks cover direct evidence, protected-slice harm, context cost, latency, capacity, disabled equivalence, and forced failure. Only admitted candidates receive answer generation. Answer promotion covers FAMA magnitude and uncertainty, FAA, MPA, reader-specific direction, and cost. Every failed check is logged.

This mechanism is \emph{self-optimization} within a bounded policy space: controlled feedback changes candidate parameters or auxiliary rules, while frozen downstream feedback decides whether the system state changes. It is not unconstrained self-modification.

\subsection{Operational versus semantic fallback}

Exact \base fallback is operational safety: a broken sidecar does not break the base service. It is not semantic safety. \base may still retrieve obsolete information. We test exact fallback extensively but never interpret it as correctness.

\section{Experimental Protocol}

\subsection{Public datasets and adapters}

Memora revision \texttt{a6493188efc836d6511ed5e4163fe3ba87da30ff} contains 600 questions, 27,614 session files, 10 personas, and weekly, monthly, and quarterly horizons. The data-manifest SHA-256 is \texttt{dfc82711...331bfc}. Only shared-memory turns enter the L0-shaped index. Memora supports answer-level current/obsolete criteria but lacks programming scope.

MemOps provides 403 paired instances, 2,558 operations, and 2,006 longitudinal probes with explicit targets. It is used for oracle state-management diagnostics. LongMemEval-V2 revision \texttt{2cc8c540} contributes 200 selected small-tier questions and 1,870 text trajectories for state-transition, procedure, and compression experiments. Dataset readers implement replaceable task, event, provenance, and metric interfaces; the main policy code does not depend on one public schema.

\subsection{Metrics and aggregation}

For one judged answer, MPA scores required valid facts and FAA scores avoidance of invalid facts. Following Memora, we compute
\[
\mathrm{FAMA}_a=\max\left(0,\mathrm{MPA}_a-\lambda_a(1-\mathrm{FAA}_a)\right),
\qquad
\lambda_a=\frac{N_{f,a}}{N_{p,a}+N_{f,a}}.
\]
The aggregation order is explicit: compute MPA, FAA, and FAMA for each judged answer; average the MiniMax-reader/DeepSeek-judge and DeepSeek-reader/MiniMax-judge cells for each case--arm; then take the arithmetic mean over the frozen case population. We do not apply the nonlinear FAMA formula after separately averaging population MPA and FAA.

The direct evidence proxy requires current-session provenance plus normalized value occurrence and penalizes obsolete exposure. It is deterministic and cheap, but cannot determine whether an answer affirms, negates, or merely narrates an old value. All primary intervals are paired persona-cluster bootstrap intervals with frozen seeds.

\subsection{Model evaluation}

MiniMax-M3 and DeepSeek-V4-Flash~\cite{minimax2026m3,deepseek2026v4} are the current readers and judges. The conditioned panel generates each answer once and records both judges; the primary estimate excludes self-judgment. D16 uses a stricter assignment: every MiniMax answer is judged only by DeepSeek, and every DeepSeek answer only by MiniMax. Thinking is disabled and exact model IDs, official endpoints, sampling, retry semantics, and unclear-verdict handling are frozen. Agreement between model judges is not human correctness.

\subsection{Chronology and data use}

The original 50-case panel is conditioned on a visible \base failure: among 192 quarterly forgetting-bearing questions, 61 expose an obsolete \base Top-5 value, and five cases per persona are selected by seeded hash. It contains 43 recommending and seven remembering questions. It estimates mechanism efficacy under stale exposure, not population impact.

D16 takes all remaining 200 quarterly questions unused by either earlier 50-case answer panel. It is a census of those remaining cases and does not condition on arm outcomes or \base stale exposure. Nevertheless, quarterly Memora had been observed during earlier proxy development, so D16 is not a pristine external-dataset holdout. Its purpose is broad robustness and causal policy-factor comparison.

\subsection{Work and call volume}

The lifecycle benchmark contains 54 versioned protocol JSON files, 251 TypeScript source/test files (50 test files), and machine-readable raw, summary, decision, admission, and independent-validation artifacts. Excluding a legacy GPT-4o-mini secondary run and avoiding double-counting byte-identical reused cells, the current MiniMax/DeepSeek studies make 2,456 reader calls and 3,018 judge calls (5,474 total). D16 alone consumes 2,805,144 API tokens.

\section{D1--D15 Research Program: Hypotheses, Tests, and Decisions}
\label{sec:d1d15}

D1--D15 form a sequence of bounded causal tests. Each direction changes one policy component or auxiliary representation, freezes its data boundary and gate before scoring, and preserves a failed result in the research ledger. Development evidence may propose the next direction; only validation or untouched-test evidence can confirm it. The sequence is organized below by the mechanism under study.

\subsection{D1--D4: Invalidation and Budgeted Context}

\paragraph{D1: obsolete-value shielding.}
\textbf{Hypothesis.} A redirected V1 context can still quote an invalidated value, so masking only that value should reduce answer contamination while preserving the candidate identity and retrieval order. \textbf{Test.} D1 keeps V1 item ids, ordering, count, and answer protocol fixed and changes only the rendered obsolete span on the frozen answer panel. \textbf{Result.} Obsolete-value context exposure falls from 74\% to 8\%, and FAA rises, but MPA falls by 2.02 points with a negative confidence interval. \textbf{Decision.} Reject on answer safety. The removed span often carries an entity anchor needed to bind the successor to the question.

\paragraph{D2: query-risk routing.}
\textbf{Hypothesis.} Shielding may help queries that only need the current value and harm queries that need the predecessor as an anchor; a query-observable router could choose between V1 and D1. \textbf{Test.} A cross-fitted surface-feature rule is learned without evaluating a case using a rule fitted on that same case. The selected V1 or shielding context then enters the unchanged answer protocol. \textbf{Result.} FAA gains 2.83 points, MPA loses 1.15 points, and the DeepSeek-reader FAMA direction remains negative. \textbf{Decision.} Reject. The available lexical features do not identify anchor dependence with sufficient reliability.

\paragraph{D3: delete-vacancy refill.}
\textbf{Hypothesis.} A delete tombstone can consume a Top-$k$ slot without supplying answer evidence; continuing through the same base candidate pool should recover a valid item. \textbf{Test.} D3 changes only vacancy handling, never expands beyond the frozen base pool, and retains the original result-count cap. \textbf{Result.} The direct proxy rises 1.40 points, below the preregistered 2-point gate, while tokens rise 2.89\%. \textbf{Decision.} Reject on effect size and cost before answer generation.

\paragraph{D4: valid-state packing.}
\textbf{Hypothesis.} A fixed number of items does not bound context length; joint item and token packing can increase valid-state density within the V1 token envelope. \textbf{Test.} Nine count--budget combinations are evaluated on development feedback, one policy is selected, and its parameters are frozen for a fresh 50-case answer panel. \textbf{Result.} FAMA rises 1.16 points and tokens fall 3.27\%, but the 95\% interval is $[-0.14,+2.90]$ points. \textbf{Decision.} Record as a near miss and reject on uncertainty.

\subsection{D5--D6: Explicit State and Incumbent Preservation}

\paragraph{D5: target-keyed state projection.}
\textbf{Hypothesis.} Matching invalidated value substrings is entity-ambiguous; explicit MemOps operation targets should produce a more faithful current-state view. \textbf{Test.} Update, Delete, and No-op operations are projected by target key on separated development, validation, and untouched-test partitions, then compared with value-linked V1 state. \textbf{Result.} Untouched-test state-FAMA rises 6.46 points with CI $[-2.40,+15.10]$, while four Update cases are harmed. Inspection shows that an independently packed target view can omit current or unknown evidence already recovered by V1. \textbf{Decision.} Reject the standalone projection.

\paragraph{D6: incumbent dominance guard.}
\textbf{Hypothesis.} Target-keyed state should be admitted only when it preserves every current or unknown incumbent item and introduces no obsolete item. \textbf{Test.} A dominance guard returns V1 whenever the candidate fails that set-level invariant. The rule is audited on already consumed D5 data because it was proposed after observing D5 failures. \textbf{Result.} State-FAMA rises 6.11 points, with 28 improvements and zero harms. \textbf{Decision.} Retain as post-hoc viability evidence only; a fresh confirmation set is required.

\subsection{D7--D11: Transition and Procedure Memory}

\paragraph{D7: state-transition diffs.}
\textbf{Hypothesis.} Raw browser or tool states contain repeated static content; a pre/action/post difference unit should expose task-relevant change more directly. \textbf{Test.} Accessibility-tree transitions are indexed alongside Base FTS5, with a fixed development-selected retrieval policy evaluated on validation. \textbf{Result.} Direct support rises 8.13 points on development and reverses to $-6.67$ points on validation; tokens rise 3.50\%. \textbf{Decision.} Reject for failed transfer.

\paragraph{D8: learned utility with a null action.}
\textbf{Hypothesis.} D7 mixes useful and irrelevant transitions; an empirical utility gate plus an explicit no-change action can suppress unsafe substitutions. \textbf{Test.} Utilities are estimated from consumed transition outcomes and the frozen gate is run on untouched test data. \textbf{Result.} Tokens fall 2.92\%, but direct support is exactly equal to Base for every scorable case and no case improves. \textbf{Decision.} Reject as a quality strategy; retain the null-action result as a compression clue.

\paragraph{D9: outcome-gated procedure memory.}
\textbf{Hypothesis.} Successful trajectories should yield reusable procedures, whereas failed trajectories should be down-weighted at write time. \textbf{Test.} A binding-safe procedure capsule is admitted by whole-trajectory outcome, with an outcome-agnostic ablation evaluated before the selected strategy is frozen for validation. \textbf{Result.} The outcome-agnostic ablation is better on development, and the frozen candidate loses 11.11 direct-support points on validation. \textbf{Decision.} Reject. Terminal outcome is too coarse for step-level credit because failures may contain useful prefixes and successes may contain detours.

\paragraph{D10: locally verified substitution.}
\textbf{Hypothesis.} Local state progress offers finer credit than terminal outcome, and restricting replacement to Base items from the same trajectory should control contamination. \textbf{Test.} D10 creates a locally verified action skeleton and substitutes only eligible same-trajectory items under a fixed budget. \textbf{Result.} Tokens fall 33.55\%, but a decisive StaticText leaf containing the correct value \emph{priority} is removed; local feedback produces no support gain. \textbf{Decision.} Reject on evidence safety. Preserving action structure alone does not preserve body text, code, or diagnostic evidence.

\paragraph{D11: evidence-preserving substitution.}
\textbf{Hypothesis.} Compression is admissible only when every bounded semantic leaf, source, order relation, and unrelated Base item survives. \textbf{Test.} A certificate checks those invariants before one same-trajectory capsule can replace Base items; any certificate, capacity, timeout, or integrity failure returns exact Base. The checksum-frozen test has 30 questions, 12 with directly computable answer-atom support. \textbf{Result.} Mean tokens fall 20.84\%; all 12 direct questions equal Base, with zero improvements and zero harms. \textbf{Decision.} Reject under the frozen quality-improvement objective and retain as an efficiency result. Section~\ref{sec:d11eff} reports the full cost evidence.

\subsection{D12--D13: Evidence Reach and Residual Repair}

\paragraph{D12: same-trajectory external expansion.}
\textbf{Hypothesis.} D11 only compresses evidence already accessible to Base; adding at most one Base-missing item from the same trajectory may recover a missing answer atom. \textbf{Test.} The fixed Base budget and index remain unchanged. The rule considers same-trajectory Top-40 candidates, adds at most one without reading answers, and never tries a second candidate after failure. \textbf{Result.} Development direct support falls 3.33 points relative to Base and five cases are harmed. \textbf{Decision.} Stop at development and reject the expansion.

\paragraph{D13: residual-feedback patch.}
\textbf{Hypothesis.} D12 should be restricted to cases matching a previously observed missing-evidence signature. \textbf{Test.} Consumed failures define the frozen signature; nonmatching queries return Base exactly. \textbf{Result.} All 23 directly scorable questions equal Base while tokens rise 0.99\%. \textbf{Decision.} Reject for no quality effect. Rule activation did not create new answer-accessible evidence.

\subsection{D14--D15: Premise Refutation Under Sparse Coverage}

\paragraph{D14: premise-refutation retrieval.}
\textbf{Hypothesis.} Some failures arise because a query presupposes an obsolete fact; retrieving a direct refutation should prevent that premise from entering the answer. \textbf{Test.} A deterministic trigger is evaluated on 33 premise questions and 25 controls, and reader calls are made only for changed contexts. \textbf{Result.} Two premise cases trigger and no control case does, but all four changed reader cells equal Base. \textbf{Decision.} Reject for low coverage and no answer effect.

\paragraph{D15: typed refutation contract.}
\textbf{Hypothesis.} Explicit \emph{premise}, \emph{refutation}, \emph{witness}, and \emph{scope} fields should make valid counterevidence easier for a reader to consume. \textbf{Test.} The renderer is first audited on the two consumed D14 triggers, then frozen. A new validation first measures trigger coverage over 23 premise and 20 control questions; answer calls are authorized only if coverage passes. \textbf{Result.} Three of four consumed design reader pairs improve, but all 43 validation contexts are exact Base no-ops because the trigger fires zero times. \textbf{Decision.} Reject on zero validation coverage. The early stop is a protocol decision, and no validation answer calls are attempted.

\section{D16: Broad Baselines and Single-Factor Ablation}

\subsection{Design and integrity}

D16 freezes 200 cases across ten personas: 100 reasoning, 62 remembering, and 38 recommending questions; 92 contain forgetting criteria and only six are Base-stale-exposed. Thirteen arms include \base, \vone, four simple baselines, six isolated \vtwo factors, and combined \vtwo:
\begin{itemize}
  \item tombstone refill and latest-write-wins;
  \item pure recency Top-5 and explicit superseded/history rendering;
  \item \vone with two hops, one extra slot, two extra slots, threshold .91, threshold .96, or aggregate protection;
  \item combined \vtwo.
\end{itemize}

The design contains 2,600 case--arm contexts. Reader message arrays that are byte-identical within one case are generated and judged once, then reused. This yields 947 unique prompts per reader and 1,894 reader plus 1,894 crossed-judge calls instead of 5,200 reader calls. There are zero retries, reader/judge model mismatches, or self-judgments. Two unclear verdicts are counted incorrect. An independent parser rescored all 1,894 raw evaluations, reconstructed 13 arm aggregates and 12 comparisons against \vone, and found zero mismatch.

\section{D17: Does Stance Repair the Proxy?}

The released direct proxy penalizes normalized obsolete-value occurrence without distinguishing affirmation, negation, or historical narration. D17 freezes an English marker-based stance proxy: affirmed, negated, and historical mentions receive exposure weights 1.0, 0.25, and 0.1. It ranks all 13 D16 policies without reading answer outcomes for the weights.

Kendall's $\tau_b$ with answer FAMA rises from 0.5290 to 0.5385, an improvement of 0.0094 against a frozen 0.10 requirement. Correlation with MPA rises from 0.4774 to 0.4872 and with FAA from 0 to 0.0129. Pairwise direction agreement against \vone remains 8/12. Both proxies correctly predict the observed \vtwo--\vone FAMA direction, but the overall gate fails.

This negative result rules out a tempting shortcut. Simple stance markers improve a few descriptions but do not substitute for semantic or answer-level evaluation. A learned proxy would require human calibration and still needs a downstream promotion boundary.

\section{D18: Text-Only Correction Construction}
\label{sec:d18}

\subsection{Protocol}

D18 directly addresses the quasi-oracle edge construction in V1. Runtime inputs are restricted to session id, persona, shared conversation text, and at most 512 earlier shared units from the same persona. Session type, operation, operation details, evaluation questions, and evidence labels are forbidden. A frozen deterministic detector recognizes explicit removal, no-longer, completion, used-to/now, from/to, preference shift, and replacement cues. A weighted lexical linker emits at most three predecessor ids and abstains when no prior unit passes its threshold.

Quarterly histories are deduplicated from weekly/monthly prefixes and split by persona: four development, three validation, and three test personas. Released operations are attached only after prediction to define invalidating sessions, kinds, obsolete values, and predecessor units. No answer-model calls are authorized.

Detecting that a correction occurred is substantially easier than deciding exactly what it invalidates. We therefore classify all V1 answer results as oracle-management evidence and reject an end-to-end construction claim.

\section{D11: Separate Efficiency Evidence}
\label{sec:d11eff}

D11 replaces selected same-trajectory \base items with one bounded capsule only if it preserves every extracted semantic leaf, source order, provenance, unrelated \base item, item count, and token certificate. Otherwise it returns exact \base. The checksum-frozen LongMemEval-V2 test contains 30 questions, of which 12 have directly computable answer-atom support.

Across all 30 questions, D11 accepts 19 substitutions and reduces mean injected tokens from 2,796.8 to 2,213.9, a 20.84\% reduction. On the 12 direct questions, \base and D11 both score 0.2083; zero improve, twelve are equal, and zero are harmed. Query p95 moves from 227.5 to 231.1 ms; selection p95 is 3.08 ms. Token, coverage, provenance, capacity, and forced-fallback violations are zero.

The frozen objective required a quality improvement, so D11 is correctly rejected for quality promotion and no answer generation is admitted. Equal direct support is not answer-level noninferiority. We retain the result only as a measured support--cost Pareto point and propose a new efficiency-specific protocol with an answer noninferiority margin.

\section{Discussion}

\subsection{What actually works}

Correction-linked redirection can improve downstream answers when the base context contains invalidated memory. It is fixed-budget, bounded, auditable, switchable, and compatible with an existing retriever. The stronger general result is the promotion architecture: V2, D1, D4, and D17 each show how a plausible or positive direct signal can fail an answer, uncertainty, or cost boundary.

The broad data suggest a risk--coverage policy rather than unconditional lifecycle rewriting. Forgetting-bearing and recommending slices benefit, while remembering MPA can be harmed. This does not yet define a deployable router: subgroup labels are diagnostic and the routing hypothesis was formed after D16 outcomes. Fresh data are required.

\subsection{What did not work}

More slots trade recall against obsolete exposure and cost. More hops are not automatically helpful. Recency saves tokens but loses quality. Explicitly rendering superseded facts costs more and does not dominate. Whole-trajectory outcome labels are too coarse for procedural memory. Preserving action structure without semantic leaves is unsafe. Typed refutation cannot transfer when its trigger has zero coverage. English stance markers do not align the proxy enough. Finally, lexical event-to-predecessor linking is unsafe despite strong event classification.

\subsection{Transfer to programming sessions}

The portable interfaces are event, scope, candidate, provenance, feedback, metric, and report adapters. An internal programming adapter should represent validity over a composite key such as
\[
(\text{repo},\text{branch},\text{base commit},\text{worktree},\text{environment},
\text{task phase},\text{file/symbol},\text{claim type}).
\]
Each claim should be active, superseded, or unknown. Unknown scope must abstain rather than invalidate.

Promising unvalidated extensions include executable witnesses (test command, exit code, commit, file hash, environment), implicit candidates from Git diff/rename/revert and test-state changes, memory rebase after branch or commit transitions, and contamination-differential evaluation that checks whether injected memory changes plans, edits, tests, or patches. A public or internal ``RepoDriftBench'' adapter could expose these fields without changing the lifecycle controller. These are designs, not results in this paper.

\subsection{Cost and confidence}

D16 demonstrates a practical two-fidelity workflow. Exact context metrics and prompt reuse cheaply eliminate many candidates; answer calls are reserved for frozen arms and unique prompts. This saved 63.6\% of otherwise required reader calls in D16. Yet two model judges may share biases. The next evidence priority is a human-calibrated subset, not another larger proxy search.

\section{Limitations}

First, Memora is personalized dialogue rather than software engineering. It lacks repository, branch, commit, worktree, environment, component, and test scope. Second, all quarterly questions were visible to earlier proxy analysis; D16 cases are answer-unconsumed but not a pristine dataset holdout. Third, the original 50-case panel is deliberately conditioned on stale exposure and cannot estimate total-traffic impact. Fourth, model-judge agreement does not establish human correctness. Fifth, D11 has only 12 direct-support questions and no generated-answer noninferiority test. Sixth, D18 uses deterministic English cues and operation-derived scoring; it does not cover implicit code-state invalidation. Seventh, exact \base fallback protects availability, not semantic correctness. Finally, D1--D18 involve repeated scientific exploration. We preserve protocol chronology and negative results, but only a fresh external or internal dataset can support deployment claims.

\section{Reproducibility and Artifacts}

Every main experiment records dataset revision or manifest, protocol version, selection or census rule, seed, model configuration, raw JSONL, summary, decision, cost, fallback checks, and claim boundary. D16 provides a raw-evaluation SHA-256, independent reconstruction, and zero mismatch report. D18 provides frozen persona splits, forbidden runtime fields, per-session predictions, and artifact hashes. The structured direction registry distinguishes passed, rejected, near-miss, post-hoc, and efficiency-only outcomes.

The implementation remains a sidecar. Disabling it, corrupting its structure, forcing timeout, exceeding capacity, or encountering a cycle returns the original base call. Dataset adapters can be replaced without rewriting policy and reporting logic.

\section{Conclusion}

We studied memory self-optimization as controlled lifecycle policy evolution rather than unconstrained rewriting of a memory engine. Fixed-budget correction-linked management produces large gains when obsolete \base evidence is present and confirmed gains on forgetting-bearing broad cases, but it is not supported as an unconditional default. A richer proxy-selected policy, simple temporal baselines, isolated factors, and a stance-aware proxy all fail frozen promotion. Text-only correction detection is accurate, but automatic predecessor linking is not. Evidence-preserving compression reduces measured context cost but still needs answer-level noninferiority.

The final strategy is conservative: retain \base, activate lifecycle management only under high-confidence scoped evidence and a freshly validated risk gate, promote quality and efficiency on separate tracks, abstain on ambiguous links, and preserve exact operational fallback. The next substantive research problem is scoped, witness-backed invalidation for repository state---not a larger Top-k.
