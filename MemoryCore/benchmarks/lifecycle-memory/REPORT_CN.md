# 面向多轮交互式长编程任务的记忆自优化

## 调研、方法、D1--D18 实验与最终策略报告

> 版本：2026-08-24（负责人汇报版）<br>
> 基座：TencentDB-Agent-Memory / MemoryCore `v2.0.0-beta.1`<br>
> 公开验证：Memora、MemOps、LongMemEval-V2<br>
> 文档分工：本文用中文说明背景、投入、实验与决策；英文论文 `paper/main.tex` 给出研究方法、统计协议和完整过程。<br>

## 0. 一页结论

这项工作不是“调了一个更好的 Top-k”，而是围绕长期记忆的**更新、失效、检索、组织、压缩和晋升**做了 18 个连续研究方向，并建立了一个可拒绝错误优化的受控自优化框架。

最终结论有五点：

1. **V1 的纠错链机制确实有用，但只在需要它的高风险流量上证据充分。** 早期 50 个“Base 已经检索到过时记忆”的条件样本中，V1 将答案 FAMA 提升 8.09 个百分点；新完成的 D16 广覆盖 200 题实验中，全量平均只提升 1.42 个百分点，置信区间触及零。92 个遗忘题提升 2.96 个百分点且区间为正，38 个推荐题提升 7.68 个百分点；62 个纯记忆题则出现 MPA 下降 1.53 个百分点的伤害信号。因此 V1 是**条件型研究 incumbent**，不是全流量默认策略。
2. **V2 被正确淘汰。** 它把阈值、两跳、额外槽位和历史保护一起做大，检索代理更好，但在条件答案面板中相对 V1 的 FAA 下降 4.08 个百分点、FAMA 下降 0.43 个百分点、token 增加 37.53%；D16 中也没有通过成本与置信度门槛。说明“检索看起来更好”不能直接代表“答案更好”。
3. **D11 是独立的效率结果。** 在 LongMemEval-V2 未触碰的 30 题测试上，证据保真压缩把平均注入 token 从 2,796.8 降到 2,213.9，减少 20.84%；12 个可直接评分问题全部与 Base 相同，没有支持度损失。但没有做答案级非劣验证，所以只能作为待确认的效率候选，不能宣称回答质量等价。
4. **新创新 D17、D18 都给出了有用的负结果。** D17 的“立场感知代理指标”只把策略排序相关性从 0.529 提到 0.538，未达到门槛；D18 只用原始对话文本检测纠错事件，测试集精确率 97.89%、召回率 79.64%，但把纠错链接回正确旧记忆的精确率只有 20.05%。这证明“发现发生了纠错”和“判断具体哪条记忆失效”是两个难度完全不同的问题。
5. **当前最可信的优化策略是分轨、分风险晋升。** 质量轨由 Base/V1 竞争，只有高置信纠错关系且查询确实有遗忘风险时才允许 V1；效率轨单独验证 D11；任何代理候选必须经过答案级、成本和 fallback 门槛，失败就保留 incumbent。自动构链未通过时必须 abstain，不能把相似历史强行判成失效。

一句话概括成果：**我们验证了“已知纠错关系后的有界生命周期管理”在高风险场景能改善答案，也验证了错误扩张、错误代理和错误自动构链会怎样失败；最终产物是一套能提出候选、更能拒绝坏候选的记忆自优化协议。**

## 1. 背景：为什么长编程任务特别需要记忆生命周期

MemoryCore 提供 L0 对话、L1 原子记忆、L2 场景、L3 画像，以及 FTS5、向量检索、多路融合、抽取和注入等基座能力。它解决了“历史信息如何被保存和找回来”，但默认的 `maxResults`、候选池、抽取、写入和注入预算大多是静态配置。

长编程任务的问题不是只会“忘记”，还会“记住已经不再成立的东西”。例如：

- 用户先要求 REST，后改为 GraphQL；
- 接口 `UserService` 后来改名为 `AccountService`；
- 实现方案被推翻或回滚；
- 当前工作从 `main` 切到旧 release branch；
- Python/Node/JDK 版本或测试环境发生变化；
- 某个测试失败只在旧 commit 上成立；
- 用户撤销了之前的功能要求。

FTS5 或向量检索只知道“这段文本与当前问题相似”，并不知道它仍然有效。它可能同时返回旧约束和新约束，甚至让旧约束因关键词更相似而排在前面。简单删除旧记忆也不理想：删除会丢掉历史和纠错来源，系统无法回答“为什么改成这样”，历史问题也会缺证据。

因此，本课题把记忆看成有生命周期的状态：

```text
旧记忆 active
   │ 用户纠错 / 更新 / 撤销
   ▼
旧记忆 superseded ─────► 新记忆 active
   │                         │
   └── 保留历史与来源        └── 当前查询优先使用
```

研究目标不是重写 FTS5、向量引擎或抽取模型，而是在基座之上增加一个**有界、可关闭、可回退的生命周期旁路**，再用公开反馈决定旁路策略是否值得晋升。

这一问题与前沿工作形成互补：Memora 把遗忘纳入 FAMA；MemoryAgentBench 将选择性遗忘列为四项核心能力之一；MEMPROBE 指出任务完成与实际留下的可恢复记忆是两种不同能力；Graphiti/Zep 使用时间有效区间保留历史；面向代码 Agent 的 SWE-MeM、subtask-level memory 和 ToM-SWE 则分别说明压缩时机、记忆粒度、持续用户状态会影响长程编程效果。相关原始来源见本文第 12 节。

## 2. 先把名词说清楚：Base、V1、V2、D11、D12 到底是什么

### 2.1 Base

**Base** 是未启用自适应能力时的 MemoryCore 基座路径：使用同一套 SQLite FTS5 / 向量候选、原始排序和原始注入预算。它既是对照组，也是所有旁路失败时必须返回的路径。

### 2.2 V1：纠错链固定预算重定向

**V1** 的完整名称是 `lifecycle-adaptive-v1.0`。其行为是：

- 写入侧从 Memora 发布的更新/删除元数据中构造“旧记忆 → 新记忆/删除事件”关系；
- 查询仍先走 Base；
- 如果 Base Top-5 命中一个已经失效的前驱，V1 沿高置信纠错边重定向到后继；
- 最终仍返回最多 5 条，不靠增加上下文换分；
- 参数固定为置信阈值 0.85、最多一跳、最多 64 次扩展、旁路预算 10 ms；
- 关闭、结构损坏、循环、超时或容量异常时，整次调用精确返回 Base。

V1 验证的是：**如果系统已经知道哪条记忆被哪次纠错替代，如何安全地管理和检索它。** 它此前并没有证明纠错关系能从原始文本自动可靠抽取；D18 专门补测了这个缺口。

### 2.3 V2：多个增强因素的组合策略

**V2** 的完整名称是 `lifecycle-contextual-v2.1`。它从 36 个候选中由直接代理指标选择，组合了：

- 置信阈值从 0.85 提到 0.96；
- 一跳变两跳；
- 根据重定向数量额外增加最多两条注入槽位；
- 对历史汇总/比较查询绕过“最新值覆盖”。

V2 是一个典型的“代理指标赢家”：它在直接检索指标上超过 V1，但答案级遗忘安全和成本更差，因此没有晋升。

### 2.4 D1--D18

**D 编号不是产品版本，而是研究方向编号。** 每个方向只回答一个更窄的问题，冻结协议后再判定：

- D1--D6：如何过滤过时证据、装箱当前状态并保护 incumbent；
- D7--D13：能否从 Agent 状态变化和过程轨迹学习可复用记忆；
- D14--D15：能否用结构化反驳证据阻止错误前提；
- D16：广覆盖答案实验、强简单基线和 V2 单因素消融；
- D17：能否用立场感知改进便宜代理；
- D18：能否不依赖发布的 operation 字段，直接从文本检测纠错并自动构链。

### 2.5 D11 与 D12 的区别

- **D11 证据保真压缩**：只压缩已经进入 Base 上下文的同轨迹内容，必须保留其中每个可界定的语义值和来源。它能省 token，但不能召回 Base 原本没取到的证据。
- **D12 轨迹一致外部证据扩展**：试图从 Base 注入前缀之外的同轨迹候选中补答案证据。它改变了证据可达性，但开发集相对 Base 反而下降，因此被淘汰。

## 3. “自优化”是怎样发生的

本项目没有把模型权重重训，也没有永久替换索引。自优化发生在受限策略层：

```text
公开反馈 / 受控结果
        │
        ▼
候选提出器：在冻结的参数、规则或组织空间中选候选
        │
        ▼
便宜门槛：覆盖、直接证据、token、时延、容量、fallback
        │ 通过
        ▼
答案门槛：MPA、FAA、FAMA、置信区间、分模型方向
        │
   ┌────┴────┐
   │全部通过 │任一失败
   ▼         ▼
晋升候选    保留 incumbent，并记录失败原因
```

这套机制的关键不是“每次都找到更高分方案”，而是：

- 能利用反馈更新阈值、槽位、渲染或辅助结构；
- 策略空间有上限；
- 评价协议在看分数之前冻结；
- 质量和效率使用不同门槛；
- 被淘汰方向保留结果，不能换子集刷分；
- 任何旁路故障都回到 Base。

这里还要区分两种安全：

- **运行安全**：异常时能否精确回退 Base；当前实现已反复验证。
- **语义安全**：Base 自己是否给了正确、最新的记忆；fallback 不能保证这一点。论文不会把两者混为一谈。

| D4 新面板 | 142 | 284 | 29 个 no-op 成对复用，避免解码噪声 |

## 5. 评测为什么可信，又有哪些不可信

### 5.1 指标

- **MPA（Memory Presence Accuracy）**：答案是否包含应当记住的当前事实。
- **FAA（Forgetting Absence Accuracy）**：答案是否避免使用已失效事实。
- **FAMA**：先对每个答案计算 `max(0, MPA - λ × (1 - FAA))`，其中 `λ` 是该题遗忘标准占全部标准的比例；再对两个交叉 reader 单元求均值，最后在冻结题目总体上求均值。
- **直接代理**：注入内容中当前事实的可达率减去过时暴露惩罚。它便宜、可确定复算，但不等于答案结果。
- **代价**：平均注入 token、条数、p50/p95 时延、预算违规和 fallback。

FAMA 的聚合顺序已经显式固定，避免先对 MPA/FAA 求总体平均后再套非线性公式造成口径变化。

### 5.2 两模型交叉裁判

MiniMax-M3 与 DeepSeek-V4-Flash 同时担任 reader 和 judge：

- MiniMax 生成的答案只用 DeepSeek 作为主裁判；
- DeepSeek 生成的答案只用 MiniMax 作为主裁判；
- D16 不允许 self-judgment；
- 不清晰 verdict 一律按错误计算。

这样能降低自评偏差，但**模型一致不等于人工正确**。早期双裁判一致率 96.79%、Cohen's kappa 0.899，只能说明两个模型在协议上高度一致，不能替代人工校准。这是当前尚未补齐的 P0 证据。

### 5.3 冻结与独立重算

- 数据版本、校验值、样本、种子、模型、策略空间和晋升阈值先写入 protocol；
- 协议改变必须升版本并重跑 Base；
- D16 的独立 validator 从 1,894 条原始 verdict 重算 13 个 arm、12 个 V1 对比，差异为 0；
- D18 在预测阶段不读取 `session_type`、`operation`、`operation_details` 或评测标签，完成预测后才挂接金标准评分。

### 5.4 数据边界

- Memora 全部 600 问题在早期代理开发中已经被看过；D16 的 200 题没有用于以前的答案面板，但不是全新数据集 holdout。
- D16 比早期 50 题更广、更少选择偏差，但仍不是人工评测或真实编程流量。
- D11 只有 12 个可直接支持度评分问题，且没有答案调用。
- D18 的 gold 来自发布的 operation 元数据；这适合测 detector，不代表真实用户纠错标签天然存在。

## 6. 实验过程：我具体探索了哪些方向

### 6.1 第一阶段：V1 有效，V2 暴露“代理—答案反转”

早期主实验从 192 个季度遗忘题中选择 Base Top-5 已暴露过时事实的 61 题，再按 persona 冻结 50 题。V1 的答案 FAMA 从 0.3195 提到 0.4004，增加 8.09 个百分点；FAA 增加 8.38 个百分点，token 只增加 1.55%。这证明纠错链在“确实发生旧记忆污染”的条件下有明显价值。

随后 V2 用 36 策略直接代理选出更激进组合。直接检索指标提升，但答案相对 V1 的 FAA 下降 4.08 个百分点、FAMA 下降 0.43 个百分点，token 增加 37.53%。因此晋升器保留 V1。

这一步形成论文最核心的方法论发现：**候选提出器可以使用便宜代理，但策略晋升必须看下游答案、遗忘安全和成本。**

### 6.2 第二阶段：D1--D6 处理失效证据与当前状态

| 方向 | 做了什么 | 结果 | 决策 |
|---|---|---|---|
| D1 过时值屏蔽 | 保留 V1 候选身份，只在注入文本中遮蔽旧值 | 上下文过时暴露 74%→8%，FAA 上升；但 MPA 下降 2.02 个百分点且区间为负 | 答案门槛拒绝 |
| D2 查询风险路由 | 用交叉拟合规则在 V1 与 D1 shield 中选择 | FAA +2.83 点，但 MPA -1.15 点，DeepSeek reader 的 FAMA 方向仍为负 | 拒绝 |
| D3 删除空位回填 | 删除后不让 tombstone 占 Top-k，使用同一 Base 候选池回填 | 直接代理 +1.40 点，但没达到 +2 点门槛；token +2.89% | 拒绝 |
| D4 有效状态装箱 | 在 V1 token 上限内，从 9 个预算/条数组合中用反馈选策略 | 新 50 题 FAMA +1.16 点、token -3.27%，但 CI [-0.14,+2.90] 点 | 近失，但拒绝 |
| D5 目标键控状态 | 在 MemOps 中按 operation target 维护当前值，不再只做字符串替换 | test state-FAMA +6.46 点但 CI 跨零，4 个 Update 题受损 | 拒绝 |
| D6 incumbent 守卫 | 只有 D5 保留 V1 所有已知当前/未知项且不引入旧项时才接受 | 已消费数据中 +6.11 点、28 改善/0 受损 | 仅后验可行，需新确认 |

这组实验说明：仅删除旧词会连同实体锚点一起损伤；有显式 target 的状态管理比值字符串更合理，但组合策略必须先证明不会丢掉 incumbent 已找回的当前证据。

### 6.3 第三阶段：D7--D13 探索过程记忆和证据组织

| 方向 | 做了什么 | 关键结果 | 决策 |
|---|---|---|---|
| D7 状态差分 | 从 accessibility tree 构造 pre/action/post 变化单元，与 Base FTS5 并行检索 | development +8.13 点；validation -6.67 点、token +3.50% | 验证拒绝 |
| D8 效用门 | 从已消费变化单元学习效用，允许选择 null action | untouched test token -2.92%，支持度完全不变、0 改善 | 质量拒绝，保留压缩线索 |
| D9 结果门控过程记忆 | 只允许成功轨迹形成绑定安全的过程 capsule | development 中“不看成功标签”的消融更好；validation -11.11 点 | 拒绝 |
| D10 局部验证替换 | 用局部状态进展代替整轨迹成败，并只替换同轨迹 Base 项 | token -33.55%，但丢失包含 `priority` 正确答案的正文 StaticText | 安全拒绝 |
| D11 证据保真替换 | 保留被替换 Base 项中的所有语义叶子、顺序和来源 | test token -20.84%，12 个直接题全相同 | 质量门槛拒绝；保留效率结果 |
| D12 外部证据扩展 | 从 Base 前缀外的同轨迹候选补语义叶子 | development 相对 Base -3.33 点，5 个受损 | 开发拒绝 |
| D13 残差反馈补丁 | 只对历史失败签名应用外部扩展 | 23 个直接题全等于 Base；token +0.99% | 开发拒绝 |

最重要的机制诊断是：轨迹最终成功/失败是过粗的监督。失败轨迹也可能有正确前缀，成功轨迹也可能包含绕路；只保存动作骨架又会丢失页面正文、代码内容或诊断文本。D11 修复了“压缩不能丢证据”的边界，但它只能压缩已检索到的东西，不能创造缺失召回。

### 6.4 第四阶段：D14--D15 探索错误前提修复

D14 不再泛化检索，而是寻找“当前问题依赖了错误前提”时的反驳证据。在 33 个 premise 问题中只触发 2 个，25 个控制题零误触发；但四个变化 reader 单元全部与 Base 相同，没有答案收益。

D15 把证据渲染为明确的 `premise / refutation / witness / scope` 合同。在 D14 已消费的两个设计题上，4 个 reader 配对中 3 个改善；但新验证集 23 个 premise 问题触发数为 0，20 个控制问题也为 0，43 个上下文全部是 Base no-op。因此 D15 在调用答案模型前就被拒绝。

它不是因为余额、模型过时或评测器故障失败，而是**新数据上结构覆盖率为零**。这验证了一个节省成本的原则：先测触发覆盖和控制误触发，覆盖不过关就不要花答案模型调用。

### 6.5 第五阶段：D16 补齐广覆盖、强基线与单因素消融

共享对话审阅提出了四个关键问题：早期只测 50 个 Base-stale-exposed 样本；缺强简单基线；V2 同时改变四个因素；代理指标与答案的一致性没有系统检验。D16、D17 正是对此的直接回应。

D16 使用两个旧 50 题面板之外的全部 200 个季度问题：

### 6.6 第六阶段：D17 检验代理，D18 检验端到端构链

#### D17 立场感知代理

旧代理只要看到过时值就惩罚，无法区分“仍把旧值当真”“明确否定旧值”“只是历史说明”。D17 将三类权重设为 1.0、0.25、0.1，再比较 13 个策略的代理排名与答案排名：

- 与答案 FAMA 的 Kendall tau-b：0.5290 → 0.5385；
- 改善仅 0.0094，低于冻结门槛 0.10；

## 8. 最终建议的优化策略

### 8.1 当前可实现版本：风险门控的生命周期旁路

建议把当前方案写成三层：

1. **Base 常驻**：所有查询先获得完整 Base 结果。
2. **V1 质量旁路**：只有上游提供高置信、可定位的纠错关系，且查询属于当前状态/遗忘高风险时才允许重定向；记忆/历史查询返回 Base 或受保护路径。
3. **晋升与回退**：所有新阈值、槽位、渲染或压缩策略先跑代理，再跑答案；任何失败保留 incumbent。旁路异常精确回 Base。

注意：D16 的 task subgroup 是解释性结果，不可以直接把 benchmark 的 `recommending` 标签写成线上路由规则。真正的选择路由必须用运行时可得特征，在新的冻结数据上确认。

### 8.2 D11 单独走效率轨

D11 不与 V1 争“质量更好”，而应使用独立门槛：

- 答案 FAMA/MPA/FAA 非劣；
- token 至少下降一个预先声明比例；
- p95 时延不超过上限；
- 证据、来源、顺序和 Base 无关项不丢；
- 关闭/损坏/超时精确回 Base。

只有新数据上的答案非劣通过后，才能将 D11 作为正式效率策略。

### 8.3 构链必须允许 abstain

D18 显示 cue 检测可以做高精度触发器，但词面相似链接会产生大量误连。当前应：

- 显式 `remove X`、`from X to Y`、明确 target id 等可形成高置信候选；
- 缺少唯一实体、字段或 scope 时标为 `unknown`，不失效任何旧记忆；
- 不用任务失败单独触发永久失效；
- 弱信号只进入候选队列，等待 Git、测试、用户确认或结构化工具结果交叉验证。

## 9. 面向真实编程任务的下一创新：Scoped Lifecycle Memory

公开对话中的“我不再喜欢 X”只有一个 persona 范围；编程事实可以在不同分支、commit、环境中同时成立。下一阶段不应继续堆 Top-k，而应将记忆有效性键升级为：

```text
(repository,
 branch,
 base_commit,
 worktree_fingerprint,
 toolchain/environment,
 task_phase,
 entity/file/symbol,
 claim_type)
```

每条记忆至少有三值状态：

- `active`：在当前 scope 有直接证据；
- `superseded`：有明确后继、revert、rename 或失败证据；
- `unknown`：scope 不匹配或证据不足，不能当成当前事实注入。

可进一步加入四个创新点，但目前都属于**待验证设计**：

1. **可执行 witness**：记忆不只保存“某方案可行”，还保存支持它的 test command、exit code、commit、文件 hash 与环境；witness 失效时降低置信，而不是靠语言相似度。
2. **隐式失效信号**：Git diff、rename、revert、测试由 pass→fail、依赖锁文件变化可以提出失效候选；只有多个独立信号一致或用户显式纠错时才确认。
3. **Memory rebase**：分支切换或 rebase 后，不是全删记忆，而是按变更影响把旧 scope 的事实迁移为 active / unknown / superseded。
4. **污染差分测试**：对同一编程任务运行 Base 与 lifecycle context，直接检查被注入记忆是否改变计划、编辑文件、测试和最终 patch；把“记忆帮了什么/害了什么”作为比单纯 pass@1 更直接的标签。

可以据此设计可替换的 `RepoDriftBench` 适配协议：任务单元包含 repo、分支/commit、工作树、环境、用户纠错事件、应保留与应失效约束、可执行 witness 和污染标签。主策略只依赖通用 adapter，不绑定内部 schema。

## 11. 目前能说什么，不能说什么

### 可以说

- 在公开长对话中，当 Base 已暴露过时记忆或题目确实包含遗忘约束时，V1 的纠错链管理能改善答案。
- V1 的收益高度异质，不应全流量默认开启。
- 更高 Top-k、更多 hop 或直接代理更高，都不能作为晋升充分条件。
- D11 在当前测试的直接支持度--token 平面上形成 -20.84% 的效率结果。
- D18 能高精度发现显式纠错事件，但当前自动前驱链接不可用。
- 开关、容量、损坏和超时回退可复现；独立重算能验证结构化结果。

### 不能说

- 不能说已经在真实多轮编程任务上提升 pass@1 或任务完成率。
- 不能说 V1 在所有长对话中都有效。
- 不能说纠错链已经能从任意自然语言自动可靠构造。
- 不能说 D11 的回答质量非劣。
- 不能把 MiniMax/DeepSeek 的一致性当成人工正确率。
- 不能把 Base fallback 当作当前事实一定正确。
- 不能把 D15 的 3/4 设计改善写成有效策略，因为验证覆盖为零。

## 12. 调研定位与前沿工作

- [Memora](https://arxiv.org/abs/2604.20006)：将 remembering、reasoning、recommending 与 forgetting-aware FAMA 放入周/月级对话，发现现有 memory agents 仍频繁复用无效记忆。本项目采用其公开标签验证生命周期机制。
- [MemoryAgentBench](https://arxiv.org/abs/2507.05257)：把准确检索、test-time learning、长程理解、选择性遗忘列为四项能力，指出现有方法无法同时掌握。它支持“不能只看召回”的问题定义。
- [MEMPROBE](https://arxiv.org/abs/2606.24595)：直接审计交互后留下的记忆 artifact，显示任务完成接近饱和时，可恢复用户状态仍只有中等水平。它支持“直接记忆评测与下游任务成功需要分开”。
- [Graphiti](https://github.com/getzep/graphiti) / [Zep](https://arxiv.org/abs/2501.13956)：用有效时间窗口和来源保留时态历史。V1 与其问题意识相近，但只做 MemoryCore 上的有界 sidecar，不替换为通用时态知识图谱。
- [SWE-MeM](https://arxiv.org/abs/2606.28434)：让代码 Agent 主动或按需压缩，并用 memory-aware credit 优化任务与效率。它说明代码 Agent 的压缩时机/粒度值得学习；D11 只验证了更窄的证据保真压缩。
- [Structurally Aligned Subtask-Level Memory](https://arxiv.org/abs/2602.21611)：指出整实例记忆存在粒度错配，subtask 粒度在 SWE-bench Verified 上更好。D9--D11 的轨迹实验同样观察到整轨迹结果标签过粗。
- [ToM-SWE](https://arxiv.org/abs/2510.21903)：持续建模用户目标、约束与偏好，说明真实代码 Agent 需要跨会话状态；但本项目还没有其 stateful SWE 证据。

本项目的研究位置不是提出另一个大而全的 memory architecture，而是：**在既有 MemoryCore 检索之上，系统研究生命周期策略怎样被反馈提出、怎样被答案门槛否决，以及质量、效率、构链三条证据必须如何分开。**
