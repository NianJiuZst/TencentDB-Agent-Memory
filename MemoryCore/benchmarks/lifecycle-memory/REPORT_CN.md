## 摘要与结论

最终方案不删除历史，也不在所有问题中暴露历史。系统把可靠的更新关系保存为追加式生命周期账本：普通问题和当前态问题只注入当前有效记忆；只有查询明确询问“以前是什么”或“如何变化”时，才在一个候选槽内同时注入带标签的 `HISTORICAL / SUPERSEDED` 与 `CURRENT / ACTIVE`。删除或撤回关系永不返回旧内容。

这套方案已接入 TencentDB Agent Memory 的真实 `performAutoRecall` 链路。写入侧在新记忆成功进入向量存储、旧 ID 均通过同作用域核验后发布更新事件；召回侧从真实检索结果保留 ID、分数和作用域，加载账本、物化后继、完成当前态解析，再按查询文本决定是否构造双态视图。异常、超时、混合作用域或渲染失败均有有界回退。

最终答案评测使用 210 个 Memora 问题。生产链路共执行 420 次自动召回，生成 250 份唯一的最终 Reader 提示；随后完成 500 次 Reader 调用和 500 次异模型 Judge 调用。查询感知双态把 60 个时序问题的 criterion accuracy 从 **72.22% 提升到 99.58%**，提高 **27.36 个百分点**，人格聚类 bootstrap 95% 区间为 **[26.53, 27.78]** 个百分点；历史问题提高 **48.75** 点，变化问题提高 **33.33** 点，当前态问题差值为 **0**。150 个自然问题的提示与答案指标均保持不变，总体注入 token 仅增加 **0.54%**。独立验证从 500 条原始 verdict 重算全部指标，结果为 **0 mismatch**。因此建议采用查询感知双态方案，但只对明确历史/变化查询开放。

## 1. 方案原理

旧记忆“过时”并不等于“永远无价值”。对于“我现在喜欢什么”，旧值会污染答案，系统应只提供新值；对于“以前喜欢什么”或“偏好如何变化”，只保留新值会造成不可回答。最终方案把两种需求拆成两个读取视图，而底层仍保留同一条可审计更新链。

```text
对话写入 → L1 抽取/去重 → update 或 merge
                              │
             同作用域旧 ID 全部核验 + 新记录可查询
                              ▼
               lifecycle-events/*.jsonl
                              ▼
检索候选 → 加载可信更新边 → 物化后继 → 当前态解析
                              ▼
       当前/普通/汇总查询：只返回 CURRENT / ACTIVE
       历史/变化查询：返回 HISTORICAL + CURRENT
                              ▼
         最终提示注入 → 数值指标 → 离线答案门禁
```

触发双态必须同时满足五个条件：更新事件为 `update`；置信权重不低于 0.85；前驱确实出现在本次原始候选中；事件与查询处于相同 team/user/agent/task 边界；问题文本被分类为历史态或状态变化。每个命中的当前候选最多配一个原始排名最靠前的前驱。删除关系、低可信边、未召回前驱、当前态查询和历史汇总查询都只走当前态路径。

## 2. 反馈如何获得并形成闭环

### 2.1 写入反馈

`src/core/record/l1-writer.ts` 复用现有去重器产生的 `update` / `merge` 与 `target_ids`。系统先在相同 team/user/agent/task 过滤下批量读取旧记录，确认全部目标真实存在；再写入新记录并确认向量存储 `upsert` 成功。只有这两个条件都成立，才通过 `appendLifecycleFeedbackEvent` 发布“前驱 ID → 后继 ID”的结构化事件。update 与 merge 的策略权重分别为 0.95 和 0.90，它们是发布门控值，不是统计校准概率。账本使用 `StorageAdapter`，可落本地或 COS；追加失败不阻断主写入。

### 2.2 在线运行反馈

`src/core/report/metric-tracking-recall.ts` 只上报数值：运行模式、重定向数、双态配对数、回退数和旁路时延，不上传记忆正文或 ID。生产灰度时据此观测后继可物化率、回退率、双态触发率、作用域异常和时延。

### 2.3 离线质量反馈

生产提示交给两个固定 Reader 生成答案，每个答案只由另一模型按冻结 criteria 判分，禁止自评。方案只有同时通过时序收益、当前态非劣、自然问题非劣、token 成本、双 Reader 方向一致、调用完整性和上下文完整性门槛，才允许晋升。这样形成“写入证据 → 生产召回 → 运行指标 → 答案评测 → 配置门禁”的闭环，而不是根据检索代理自动修改线上策略。

## 3. 代码如何接入 TencentDB Agent Memory

| 环节 | 代码位置 | 实现职责 |
|---|---|---|
| 配置与 schema | `src/config.ts`、`openclaw.plugin.json` | `feedbackEnabled`、`enabled`、`dualStateMode`；默认均保持安全关闭 |
| 结构化反馈 | `src/core/record/l1-writer.ts` | 核验旧 ID、新记录可查询后发布更新边 |
| 账本与隔离 | `src/core/lifecycle/feedback-store.ts` | 事件校验、追加、容量限制；按 team/user/agent/task 过滤 |
| 查询意图 | `src/core/lifecycle/temporal-intent.ts` | 只读查询文本，识别当前、历史、变化和历史汇总 |
| 生命周期解析 | `src/core/lifecycle/production-runtime.ts` | 过滤可信事件、物化后继、继承分数、当前态解析、受控双态渲染与回退 |
| 最终召回 | `src/core/hooks/auto-recall.ts` | 接入 keyword、embedding、SQLite hybrid、TCVDB native-hybrid 的真实 ID，并构造最终 `prependContext` / `appendSystemContext` |
| 可观测性 | `src/core/report/metric-tracking-recall.ts` | mode、redirect、pair、fallback、latency 数值指标 |

召回异常的边界是明确的：生命周期账本整体异常或超时，返回原检索前缀；双态渲染单独异常，保留已经解析出的当前态结果；混合作用域候选直接回退；后继批量查询始终携带同一隔离条件。旁路限制为一跳、最多 64 次扩展、10 ms、最多读取 5,000 个事件。

推荐目标配置如下，实际发布应先影子采集再灰度读取：

## 4. 最终生产路径答案评测

### 4.1 数据与对照

数据固定为 Memora 修订 `a6493188efc836d6511ed5e4163fe3ba87da30ff`，覆盖 10 个 persona：

- 自然面板：150 个完整周级问题，reasoning、recommending、remembering 各 50 个，用于检查普通流量是否退化。
- 时序面板：20 组结构化 preference update，每组各生成当前、历史、变化问题，共 60 题，用于检验“新旧一起返回”的能力。
- 对照组“当前态单路”：生命周期解析后只注入当前后继。
- 实验组“查询感知双态”：仅历史/变化问题注入一个带标签的新旧状态对，其余与对照组逐字节相同。

候选排名来自冻结的 `IMemoryStore` 契约适配器，保证两组输入顺序一致；配置解析、持久化事件写入/读取、作用域过滤、后继物化、查询路由、预算和最终提示构造均执行生产代码。该评测没有连接真实 SQLite、TCVDB 或 COS 网络，因此证明的是生产逻辑与答案效果，不是线上数据库延迟。

### 4.2 指标与门槛

- `criterion accuracy`：每题冻结的应出现/不应出现标准的正确比例，时序问题等权聚合。
- MPA：答案覆盖应保留事实的比例；FAA：答案避开失效事实的比例。
- FAMA：`max(0, MPA - λ × (1 - FAA))`，λ 为该题遗忘标准占比。
- 不确定性：按 persona 做配对聚类 bootstrap，5,000 次抽样，报告 95% 区间。
- 成本：比较实际生产 `prependContext + appendSystemContext` 的 token。

评分前冻结的主要门槛是：时序准确率至少提高 15 点且区间下界大于 0；历史与变化各至少提高 15 点；当前态与自然面板差值不低于 -1 点；总体 token 增幅不超过 10%；两个 Reader 的时序方向均不为负；上下文与模型调用必须完整。

### 4.3 结果

| 面板 | n | 当前态单路 | 查询感知双态 | 配对差值与 95% 区间 |
|---|---:|---:|---:|---:|
| 自然问题 FAMA | 150 | 28.72% | 28.72% | 0.00 点 [0.00, 0.00] |
| 当前态 accuracy | 20 | 100.00% | 100.00% | 0.00 点 [0.00, 0.00] |
| 历史态 accuracy | 20 | 50.00% | 98.75% | **+48.75 点 [46.25, 50.00]** |
| 状态变化 accuracy | 20 | 66.67% | 100.00% | **+33.33 点 [33.33, 33.33]** |
| 全部时序 accuracy | 60 | 72.22% | 99.58% | **+27.36 点 [26.53, 27.78]** |

时序 FAMA 从 50.00% 提升至 99.17%，提高 49.17 点；60 题中 40 题改善、20 题持平、0 题受损。两个 Reader 的时序 accuracy 方向分别为 +27.78 和 +26.94 点。全部 210 题的平均注入 token 从 549.20 增至 552.19，仅增加 0.54%。所有冻结门槛通过。

## 5. 上线与评测闭环

上线分三步：先只开启 `feedbackEnabled` 影子记录，抽样确认更新边及作用域；再开启当前态解析，验证后继可物化率和回退；最后将 `dualStateMode` 灰度为 `query_aware`，只观察明确历史/变化查询。线上至少保留以下门禁：跨作用域泄漏为 0；删除旧值暴露为 0；后继可物化率不低于 99.9%；生命周期 p95 总增量不超过 10 ms；回退率、双态触发率和历史/变化答案正确率按周复核。任一安全门失败立即关闭读取开关，账本仍可继续影子采集。

## 6. 证据边界

本实验支持“可靠更新边进入最终自动召回后，查询感知地保留新旧状态能显著改善历史与变化答案，同时保持当前和自然问题不变”。它不支持无条件暴露旧记忆，也不证明纯文本自动识别前驱、真实查询占比、人类裁判一致性、真实 COS/TCVDB 网络时延或多轮编程任务收益。Memora 周级面板曾用于此前开发，因此本次是冻结输入上的新答案证据，不是全新外部留出集。下一步应在真实流量影子日志中人工标定查询路由与更新边，再做线上分层 A/B。
