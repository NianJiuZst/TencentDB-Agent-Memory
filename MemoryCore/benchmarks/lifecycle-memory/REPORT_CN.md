# 面向多轮交互式长编程任务的记忆自优化

## 研究方法、实验过程与策略结论

> 版本：2026-08-30<br>
> 基座：TencentDB-Agent-Memory / MemoryCore v2.0.0-beta.1<br>
> 公开验证数据：Memora、MemOps、LongMemEval-V2<br>
> 研究范围：公开长对话上的方法验证；真实多轮编程任务尚待内部数据验证

---

## 摘要

本项目研究多轮交互中记忆的更新、失效、检索、组织与压缩问题。在 MemoryCore 基座检索之上，项目实现了可关闭、可回退、容量和时延有界的生命周期旁路，并建立了基于受控反馈的策略提出与晋升协议。策略层根据纠错关系、直接证据、答案质量、遗忘安全和上下文成本更新参数或辅助结构；FTS5、向量检索和基座抽取模型保持不变。

研究首先提出纠错链固定预算重定向策略 V1，并在 50 个已确认出现过时记忆暴露的问题上验证其机制效果。随后提出多因素增强策略 V2，并通过答案评测发现直接检索代理与下游答案发生反转。围绕这一问题，项目依次开展 D1--D19 共 19 个研究方向，覆盖过时证据屏蔽、风险路由、状态投影、过程记忆、证据保真压缩、前提反驳、广覆盖消融、代理校准、文本自动构链和查询感知双状态返回。

早期条件实验中，V1 相对 Base 的答案 FAMA 提高 8.09 个百分点。D16 在未按 Base 失败筛选的 200 题上得到 1.42 个百分点的全量增益，其置信区间触及零；92 个含遗忘标准的问题提高 2.96 个百分点，38 个推荐问题提高 7.68 个百分点，62 个记忆问题出现 MPA 下降 1.53 个百分点的伤害信号。V1 因此保留为高遗忘风险条件下的研究基准策略。

V2、四个简单基线及六个单因素增强均未通过预先冻结的质量、成本和不确定性门槛。D11 在 LongMemEval-V2 测试集上将平均注入 token 从 2,796.8 降至 2,213.9，下降 20.84%，12 个可直接评分问题的证据支持度与 Base 相同；该结果作为效率证据保留，答案级非劣性尚未验证。D18 的文本纠错事件检测达到 97.89% 精确率和 79.64% 召回率，但前驱记忆链接精确率仅为 20.05%，未达到自动构链要求。

D19 进一步检验“同时返回带标签的新旧记忆”。在 60 个受控时序问题上，查询感知双状态将 criterion accuracy 从 71.39% 提升至 100%，差值为 +28.61 个百分点，95% persona bootstrap 区间为 [+27.78,+29.86]；历史问题提升 52.50 点、变化问题提升 33.33 点，当前状态问题与 V1 完全相同。在 150 个自然周级问题上没有明确历史/变化查询，查询感知方案因而与 V1 字节等价；无条件双状态虽使 FAMA 提高 1.47 点，却增加 29.53% token，未过成本门。该思路被保留为默认关闭、仅对明确历史/变化问题开启的能力，不替代 V1 默认策略。

最终方案采用质量、时序、效率和构链四条独立证据轨。质量轨在 Base 与 V1 之间进行风险门控；时序轨仅对明确历史/变化查询返回一组带标签的旧/新状态；效率轨单独验证 D11 的答案非劣性；构链轨对不确定链接执行 abstain。所有候选均须通过答案级、成本、完整性与回退门槛后才能晋升。

## 1. 研究背景与问题定义

### 1.1 多轮长任务中的记忆失效

MemoryCore 提供 L0 对话、L1 原子记忆、L2 场景和 L3 画像，并支持 FTS5、向量检索、多路融合、抽取与注入。基座能够保存和检索历史信息，但返回条数、候选池、写入条件和注入预算主要由静态配置控制。

多轮编程任务中的事实具有显著的状态依赖性：

- 用户可将 REST 方案更新为 GraphQL；
- 接口、文件或符号可在后续轮次中重命名；
- 方案可被撤销、回滚或替换；
- 分支、commit、worktree 和依赖环境可发生切换；
- 测试结论可能只对某一代码版本成立；
- 已记录的用户约束可被明确取消。

词法或向量相似度只衡量相关性，不能判断事实在当前状态下是否仍然有效。永久删除旧记忆会损失历史来源、纠错链和时间比较能力。因此，本研究将记忆表示为带状态和来源的生命周期对象：

~~~text
旧记忆 active
   │ 更新、删除、撤销或纠错
   ▼
旧记忆 superseded ─────► 新记忆 active
   │                         │
   └── 保留来源与历史        └── 当前状态查询优先使用
~~~

### 1.2 研究问题

本项目回答五个研究问题：

1. 已知纠错关系时，如何在固定上下文预算内减少过时记忆对答案的污染？
2. 如何使用公开评测或受控反馈更新策略，同时防止直接检索代理晋升答案更差的方案？
3. 状态投影、过程记忆、证据压缩和前提反驳能否改善质量或降低成本？
4. 纠错关系能否从原始长对话文本中自动构造，并达到可用于记忆失效的精度？
5. 已知可靠更新关系时，哪些查询应同时看到带时态标签的旧状态与当前状态？

### 1.3 演化边界

策略演化限定在以下范围：

- 更新阈值、跳数、槽位、预算和路由规则；
- 增加有容量上限的纠错关系、状态视图、过程 capsule 或压缩结构；
- 根据冻结反馈决定候选的保留、拒绝或晋升；
- 关闭旁路时恢复 Base；
- 异常、超时、循环、损坏或容量越界时整次调用返回 Base。

本项目不修改 FTS5 和向量检索内核，不重训基座抽取模型，不使用私有编程数据形成公开实验结论。

## 2. 系统设计与候选策略

### 2.1 Base：基座路径

Base 使用相同的 MemoryCore 数据、SQLite FTS5 / 向量候选、原始排序和注入预算。Base 同时承担对照组、关闭开关后的等价路径和旁路失败时的回退路径。

### 2.2 V1：纠错链固定预算重定向

V1 的版本标识为 lifecycle-adaptive-v1.0，执行过程如下：

1. 写入侧从公开 Memora 的更新或删除操作元数据构造前驱到后继的关系；
2. 查询侧首先获得完整 Base 候选；
3. Base Top-5 命中已失效前驱时，沿高置信纠错边重定向到当前后继；
4. 去重后从同一 Base 候选池回填，最终条数不超过 5；
5. 置信阈值固定为 0.85，最多一跳，最多 64 次扩展，旁路预算为 10 ms；
6. 关闭、损坏、循环、超时或容量异常时返回字节等价的 Base 结果。

V1 检验已知纠错关系条件下的生命周期管理能力。其前驱关系来自公开结构化操作字段，因此属于结构化真值辅助的管理实验。D18 单独评估从原始文本构造关系的能力。

### 2.3 D19：查询感知的双状态返回

D19 不改变 V1 的重定向和当前状态解析，而是在 V1 已得到当前后继之后增加一个默认关闭的渲染层：

1. 只读取查询文本，以冻结规则区分 current_state、historical_state、state_change 和 historical_aggregate；
2. 仅 historical_state 和 state_change 可触发双状态；当前状态与汇总查询返回精确 V1；
3. 只接受同作用域、达到信任阈值、且旧 ID 已出现在 Base 候选中的结构化 update 事件；
4. 在同一候选槽内返回 `HISTORICAL / SUPERSEDED` 与 `CURRENT / ACTIVE`，并明确提示当前问题优先使用 active 值；
5. delete 事件永不返回旧值；渲染异常退回已经解析的 V1 后继，而不是退回含旧值的 Base。

该设计把“旧记忆是否应该出现”改成查询意图问题：当前事实查询只需要新值，历史回顾和变化解释才需要旧值及其时态。它同时保留了导师问题指出的简洁默认路径与用户提出的历史信息价值。

### 2.4 V2：代理选择的多因素增强

V2 的版本标识为 lifecycle-contextual-v2.1。候选空间包含 36 个组合：

- 置信阈值 0.85、0.91 或 0.96；
- 最大跳数 1 或 2；
- 根据重定向数量增加 0、1 或 2 个槽位；
- 对历史汇总或比较查询启用或关闭保护。

直接证据代理选择出的组合为阈值 0.96、两跳、两个附加槽位和历史保护。V2 在直接检索指标上优于 V1，答案级评测未通过晋升门槛。

### 2.5 受控自优化协议

自优化由候选提出和候选晋升两个阶段组成：

~~~text
公开反馈或受控结果
        │
        ▼
候选提出：在冻结的参数、规则或辅助结构空间中选取候选
        │
        ▼
直接门槛：覆盖、证据、token、时延、容量、回退
        │ 通过
        ▼
答案门槛：MPA、FAA、FAMA、置信区间、分模型方向
        │
   ┌────┴────┐
   │全部通过 │任一失败
   ▼         ▼
晋升候选    保留现行策略并记录拒绝原因
~~~

策略空间、数据、阈值、抽样和决策门槛均在评分前写入版本化 protocol。开发结果只用于提出下一候选，验证或测试失败后不得改子集重新解释为通过。

### 2.5 三类证据轨

- 质量轨：要求答案 FAMA 改善，同时满足 FAA、MPA、成本、完整性和回退约束。
- 效率轨：要求答案质量在预设非劣界内，并满足 token 或时延降幅。
- 构链轨：要求纠错事件、类型和前驱链接达到各自的精确率、召回率和覆盖门槛。

运行回退只保证旁路故障不会破坏 Base 服务。Base 结果本身仍可能包含过时信息，因此运行安全与语义安全分别报告。

## 3. 数据、指标与实验协议

### 3.1 公开数据与用途

| 数据 | 使用规模 | 实验用途 |
|---|---:|---|
| Memora | 600 问题、27,614 个会话、10 个 persona | V1/V2、D1--D4、D16--D19；当前事实、失效事实、时序问答与答案遗忘 |
| MemOps | 403 对实例、2,558 个操作、2,006 个纵向 probe | D5--D6；显式目标键下的更新、删除与状态管理 |
| LongMemEval-V2 small tier | 200 个选定问题、1,870 条轨迹 | D7--D15；状态差分、过程记忆、证据组织与压缩 |

数据读取、事件、来源、反馈、指标和报告均通过适配接口连接，主策略不依赖单一公开数据 schema。

### 3.2 质量与成本指标

- MPA（Memory Presence Accuracy）：答案覆盖应保留当前事实的比例。
- FAA（Forgetting Absence Accuracy）：答案避免使用已失效事实的比例。
- FAMA：对单个答案计算 max(0, MPA - λ × (1 - FAA))，λ 为该题遗忘标准占全部标准的比例；先在答案单元内计算，再对两个 reader 单元和冻结问题总体依次求均值。
- Criterion accuracy：裁判对每条冻结应保留/应避免标准的二元正确率；D19 时序面板以问题等权聚合，并分别报告 current/history/change。
- 直接证据代理：当前事实可达率减去过时事实暴露惩罚。
- 成本：平均注入 token、注入条数、p50/p95 时延、预算违规和回退次数。

直接证据代理可确定复算，不能识别答案对旧事实的肯定、否定或历史叙述立场，因此仅用于候选筛选。

### 3.3 Reader 与 Judge

MiniMax-M3 和 DeepSeek-V4-Flash 同时承担答案生成模型（reader）和裁判模型（judge）：

- MiniMax 生成的答案由 DeepSeek 主裁判；
- DeepSeek 生成的答案由 MiniMax 主裁判；
- D16 禁止 self-judgment；
- 无法解析的 verdict 按错误处理；
- 模型、端点、采样、重试和聚合顺序均由协议冻结。

早期双裁判一致率为 96.79%，Cohen's kappa 为 0.899。该结果反映模型间协议一致性，尚未经过人工裁判标定。

### 3.4 数据边界与复算

- 早期 50 题从 61 个 Base Top-5 已暴露过时值的问题中按 persona 冻结，估计条件机制效果。
- D16 使用两个早期答案面板均未消费的 200 个季度问题，不按策略结果或 Base 失败筛选。
- Memora 全部 600 问题曾用于早期代理分析，D16 属于答案未消费的广覆盖实验，不属于全新外部留出集。
- D16 独立 validator 从 1,894 条原始 verdict 重算 13 个 arm 和 12 个 V1 对比，数值差异为 0。
- D18 预测阶段禁止读取 session_type、operation、operation_details 和评测标签，预测完成后才连接金标准。
- D19 使用完整的 150 题周级自然面板，并另建 20 组结构化 preference update、三种查询意图共 60 题的受控能力面板；后者证明能力，不作为自然流量占比估计。
- D19 查询路由只读取问题文本，禁止使用题型标签、gold criterion 或模型输出；三 arm、阈值、成本门和默认替换门均在答案调用前提交。

### 3.5 实验实现与计算投入

生命周期 benchmark 当前包含：

- 56 个版本化 protocol JSON；
- 263 个 TypeScript 源文件和测试文件，其中测试文件 51 个；
- 92 个结构化结果文件，包括逐例 JSONL、summary、decision、admission 和 independent validation；
- 关闭、损坏、超时、循环、容量和结构异常的精确回退用例。

可核对的 MiniMax-M3 / DeepSeek-V4-Flash 实验共完成 3,128 次 reader 调用和 3,690 次 judge 调用，合计 6,818 次。D16 单轮使用约 2,805,144 API token；D19 使用 622,252 API token。D16 的 2,600 个问题--策略上下文经字节等价复用后，每个 reader 仅生成 947 个唯一答案，reader 调用量相对逐 arm 独立生成下降 63.6%。D19 的 630 个 case--arm 上下文经同样的字节等价复用后，每个 reader 生成 336 个唯一答案。

## 4. 研究过程与实验结果

### 4.1 V1 与 V2：条件机制效果和代理反转

早期主实验从 192 个季度遗忘问题中识别出 61 个 Base Top-5 暴露过时值的问题，并按 persona 冻结 50 个样本。该面板含 43 个推荐问题和 7 个记忆问题。

| 策略 | MPA | FAA | FAMA | 平均注入 token |
|---|---:|---:|---:|---:|
| Base | 0.3855 | 0.8531 | 0.3195 | 144.52 |
| V1 | 0.4342 | 0.9369 | 0.4004 | 146.76 |
| V2 | 0.4461 | 0.8961 | 0.3961 | 201.84 |

V1 相对 Base 的 FAMA 提高 8.09 个百分点，95% persona-cluster CI 为 [5.17, 12.59] 个百分点；FAA 提高 8.38 个百分点，token 增加 1.55%。该结果支持已知纠错关系和已发生过时暴露条件下的重定向机制。

V2 相对 V1 的 FAA 下降 4.08 个百分点，FAMA 下降 0.43 个百分点，token 增加 37.53%。V2 在直接代理上的优势未转化为答案收益，晋升器保留 V1。该实验确立了后续研究的决策原则：代理用于提出候选，答案与成本用于晋升候选。

### 4.2 D1--D4：失效证据处理与预算装箱

#### D1 过时值屏蔽

理论假设：V1 保留失效前驱的文本可能继续暴露旧值；遮蔽旧值可提高 FAA。

实验过程：保持 V1 的候选身份、顺序和条数不变，只对注入文本中的旧值执行遮蔽。在冻结答案面板上比较上下文暴露、MPA、FAA 和 FAMA。

结果与判断：过时值暴露率由 74% 降至 8%，FAA 上升；MPA 下降 2.02 个百分点且置信区间为负。旧值同时承担实体锚点和语义定位作用。D1 未通过答案安全门槛。

#### D2 查询风险路由

理论假设：D1 对部分查询有利，对需要实体锚点的查询有害；运行时风险特征可在 V1 与 D1 之间选择。

实验过程：使用交叉拟合规则，依据查询和上下文的表面特征预测屏蔽风险，禁止同一问题同时参与规则拟合和评估。

结果与判断：FAA 提高 2.83 个百分点，MPA 下降 1.15 个百分点；DeepSeek reader 的 FAMA 方向仍为负。表面特征不能稳定识别锚点依赖，D2 被拒绝。

#### D3 删除空位回填

理论假设：删除事件形成 tombstone 后会占用 Top-k；从同一 Base 候选池回填空位可恢复有效证据。

实验过程：不扩大 Base 候选边界，只在删除形成空位时继续扫描同一候选池并保持固定返回条数。

结果与判断：直接代理提高 1.40 个百分点，低于预设 2 个百分点门槛；token 增加 2.89%。D3 未达到幅度和成本要求。

#### D4 有效状态装箱

理论假设：固定条数不能保证固定 token 成本；在 V1 token 上限内联合控制条数和预算可提高当前状态密度。

实验过程：在 9 个条数--token 组合中使用开发反馈选择一个候选，并在新的 50 题面板上固定评估。

结果与判断：FAMA 提高 1.16 个百分点，token 降低 3.27%；95% CI 为 [-0.14, 2.90] 个百分点。正向点估计未达到不确定性门槛，D4 作为近失方案拒绝。

### 4.3 D5--D6：显式目标状态与现行策略保护

#### D5 目标键控状态

理论假设：按旧值字符串寻找失效对象存在实体歧义；显式 operation target 能形成更准确的当前状态视图。

实验过程：在 MemOps 中按目标键执行 Update、Delete 和 No-op 状态投影，并与 V1 的值匹配路径比较。开发、验证和未触碰测试按协议分离。

结果与判断：测试 state-FAMA 提高 6.46 个百分点，95% CI 为 [-2.40, 15.10] 个百分点；4 个 Update 问题受损。显式 target 改善状态语义，但独立投影会丢失 V1 已找回的后继证据，D5 未通过测试门槛。

#### D6 现行策略守卫

理论假设：D5 仅在保留 V1 已有当前或未知证据、且不引入旧证据时启用，可减少组合伤害。

实验过程：增加支配关系守卫；候选必须覆盖现行策略的全部受保护项，未满足时返回 V1。

结果与判断：已消费数据的后验审计中，state-FAMA 提高 6.11 个百分点，28 个问题改善、0 个问题受损。该规则形成可行性证据，因使用已消费数据提出，未晋升，需在新数据上确认。

### 4.4 D7--D11：状态变化、过程记忆与证据压缩

#### D7 状态差分

理论假设：原始页面或工具状态包含大量静态信息；pre/action/post 差分能突出任务推进所需变化。

实验过程：从 accessibility tree 构造状态变化单元，与 Base FTS5 并行检索；开发集选择固定策略后，在验证集保持参数不变。

结果与判断：开发集直接支持度提高 8.13 个百分点；验证集下降 6.67 个百分点，token 增加 3.50%。差分表示未跨数据迁移，D7 被拒绝。

#### D8 效用门与空动作

理论假设：D7 的变化单元质量不均；从已消费数据学习效用并允许 null action 可避免低效替换。

实验过程：对候选变化单元设置效用门，未达到阈值时不改变 Base；在未触碰测试上评估。

结果与判断：token 下降 2.92%，直接支持度与 Base 完全相同，改善问题数为 0。D8 未产生质量收益，压缩信号保留给后续研究。

#### D9 结果门控过程记忆

理论假设：成功轨迹包含可复用过程，失败轨迹应降低写入或检索优先级。

实验过程：将结果标签作为过程 capsule 的准入条件，并设置不读取结果标签的消融。开发选择后在验证集固定评估。

结果与判断：开发集中结果无关消融优于结果门控版本；验证集直接支持度下降 11.11 个百分点。整轨迹成败对局部步骤提供的信用过粗，D9 被拒绝。

#### D10 局部验证替换

理论假设：局部状态进展比整轨迹结果更适合作为步骤级反馈；仅替换同轨迹 Base 项可控制污染。

实验过程：依据局部状态变化构造绑定安全的过程骨架，在固定预算内替换同轨迹候选。

结果与判断：token 下降 33.55%，但一个问题中含 priority 正确答案的 StaticText 正文被移除；局部反馈未产生支持度提升。过程骨架未保留完整语义证据，D10 因安全失败被拒绝。

#### D11 证据保真压缩

理论假设：过程压缩只有在保留被替换 Base 项的全部可界定语义叶子、顺序、来源和无关项时才具备安全性。

实验过程：D11 对同轨迹项生成有界 capsule；语义叶子、来源、顺序、条数、token certificate 或 fallback 任一检查失败时返回 Base。LongMemEval-V2 未触碰测试包含 30 个问题，其中 12 个可直接计算答案原子支持度。

结果与判断：19 个替换被接受；平均 token 从 2,796.8 降至 2,213.9，下降 20.84%。12 个直接问题的 Base 与 D11 支持度均为 0.2083，0 改善、12 相同、0 受损。原质量协议要求支持度改善，因此质量晋升被拒绝；该结果作为效率候选保留，需补充答案级非劣实验。

### 4.5 D12--D15：证据可达性与错误前提修复

#### D12 同轨迹外部证据扩展

理论假设：D11 只能压缩 Base 已检索证据；从 Base 前缀之外补充一条同轨迹证据可能恢复缺失答案原子。

实验过程：保持 Base 预算，从同轨迹 Top-40 中最多加入一条 Base 未包含的候选，不读取答案，不尝试第二候选。

结果与判断：开发集直接支持度相对 Base 下降 3.33 个百分点，5 个问题受损。额外证据产生挤占或污染，D12 在开发阶段停止。

#### D13 残差反馈补丁

理论假设：D12 的扩展只应作用于历史上出现明确缺失签名的问题。

实验过程：使用已消费问题提取失败签名，仅对匹配项执行 D12 扩展，其余返回 Base。

结果与判断：23 个可直接评分问题全部与 Base 相同，token 增加 0.99%。规则被触发未带来新增答案证据，D13 被拒绝。

#### D14 前提反驳证据

理论假设：部分记忆错误表现为查询包含已失效前提；检索明确反驳证据可阻止错误前提进入答案。

实验过程：在 33 个 premise 问题和 25 个控制问题上检测反驳触发，仅对变化上下文调用 reader。

结果与判断：premise 问题触发 2 个，控制问题误触发 0 个；四个变化 reader 单元均与 Base 相同。D14 的精度较高、覆盖较低，未产生答案收益。

#### D15 类型化反驳合同

理论假设：将候选渲染为 premise、refutation、witness 和 scope 四类字段，可提高模型对反驳证据的利用率。

实验过程：先在 D14 已消费的两个触发问题上进行设计审计，再冻结 renderer，在 23 个新 premise 问题和 20 个控制问题上先测触发覆盖；覆盖门槛通过后才允许答案调用。

结果与判断：设计审计的 4 个 reader 配对中 3 个改善；新验证集 43 个问题全部未触发。D15 因验证覆盖率为零停止，未进入答案调用。该拒绝与模型服务余额或评测器故障无关。

## 6. 最终优化策略

### 6.1 风险门控的质量轨

1. 所有查询首先生成完整 Base 结果。
2. 上游提供高置信、可定位、带来源的纠错关系时，V1 才具备运行条件。
3. 运行时风险路由应使用可观测的失效证据、scope 一致性和查询意图；D16 的 benchmark 任务标签仅用于分析。
4. 当前状态或遗忘风险查询可进入 V1；关系不确定查询保留 Base 或受保护路径。
5. 新阈值、跳数、槽位和渲染候选须经过冻结答案门槛后才能替换现行策略。

### 6.2 查询感知的时序轨

- 默认 `dualStateMode=off`，V1 只注入当前 active 后继；
- `query_aware` 只根据查询文本判断是否明确询问 historical_state 或 state_change；
- 每个命中的 update 最多生成一个同槽位 transition block，旧值标为 `HISTORICAL / SUPERSEDED`，新值标为 `CURRENT / ACTIVE`；
- current_state 与 historical_aggregate 精确沿用 V1，不额外返回旧值；
- delete/retraction 永不触发双状态；渲染失败回到 V1 后继；
- 灰度同时监控触发率、每次触发 token、时序答案正确率和误触发率。

### 6.3 证据保真压缩的效率轨

D11 使用独立晋升协议：

- 预先声明答案 FAMA、MPA 和 FAA 的非劣界；
- 预先声明最低 token 降幅；
- 保留全部语义叶子、顺序、来源和 Base 无关项；
- 约束 selection 与总查询 p95 时延；
- 关闭、损坏、超时或证书失败时返回 Base。

完成新数据上的答案非劣验证后，D11 才具备正式效率晋升条件。

### 6.4 可拒绝的构链轨

- 显式 remove X、from X to Y、唯一 target id 和结构化工具事件可提出高置信候选；
- 实体、字段或 scope 无法唯一确定时输出 unknown，不修改旧记忆状态；
- 任务失败和弱纠错 cue 只产生候选，不直接执行永久失效；
- Git、测试、用户确认和结构化工具结果可作为独立 witness；
- 构链精度、覆盖、类型和误失效代价分别评估。

## 7. 面向多轮编程数据的迁移设计

### 7.1 Scope 表示

编程记忆的有效性键应至少包含：

~~~text
(repository,
 branch,
 base_commit,
 worktree_fingerprint,
 toolchain_environment,
 task_phase,
 entity_file_symbol,
 claim_type)
~~~

每条记忆使用 active、superseded 和 unknown 三值状态。scope 不匹配或证据不足时进入 unknown，避免跨分支、跨环境失效。

### 7.2 可执行 witness

编程记忆可记录以下支持信息：

- test command 与 exit code；
- commit、文件 hash 和工作树状态；
- 文件、符号、接口和依赖版本；
- 产生结论的工具调用与时间；
- 用户显式确认、撤销或方案替换。

witness 失效时降低置信或转为 unknown；明确 rename、revert、后继事实或用户纠错可形成 superseded 候选。

### 7.3 适配接口

内部数据接入仅需实现：

- SessionAdapter：会话、轮次、工具调用和任务边界；
- ScopeAdapter：repo、branch、commit、worktree 和环境；
- EventAdapter：更新、删除、撤销、重命名和回滚候选；
- EvidenceAdapter：应保留事实、应失效事实、来源和 witness；
- MetricAdapter：直接记忆效果、误删代价、答案质量和任务结果；
- ReportAdapter：基座/候选模式、k、fallback、信号、耗时和结构化结果。

生命周期控制器、晋升器和回退逻辑保持不变。

### 7.4 后续验证协议

RepoDriftBench 可将一次编程会话切分为写入、状态变化、查询和注入四类事件，并记录：

- 更新前后约束与 scope；
- 应保留和应失效的记忆；
- 可执行 witness；
- Base 与 lifecycle 注入差异；
- 计划、编辑文件、测试结果和最终 patch 的污染差异。

该协议能够同时测量记忆直接效果、下游任务结果和误失效代价。

## 8. 证据边界与局限

- 公开实验验证生命周期方法，未验证真实多轮编程任务的 pass@1 或任务完成率。
- V1 的结构化前驱关系来自 Memora 发布操作字段；D18 尚未支持可靠自动构链。
- D16 扩大了答案面板并减少条件选择偏差，全部 Memora 问题仍曾参与早期代理研究。
- D16 的分层结果用于解释异质性，尚未形成经过新数据确认的运行时路由器。
- D19 的 60 题时序面板是结构化能力探针；自然 150 题中明确历史/变化查询为 0，不能估计真实触发率或支持默认替换。
- D19 只验证正确 update 边已存在时的渲染与回答价值；不修复 D18 的自动前驱链接问题，且局部触发 token 从 7.8 增至 40.5。
- MiniMax-M3 与 DeepSeek-V4-Flash 的交叉裁判降低自评偏差，模型间一致性尚未由人工金标准校准。
- D11 只有 12 个可直接评分问题，且未进行生成答案非劣实验。
- Base 精确回退保证运行可用性，不保证返回事实的时态正确性。
- D1--D19 属于连续科学探索；最终部署结论需要全新公开集或内部编程数据确认。

## 9. 相关工作与研究定位

- [Memora](https://arxiv.org/abs/2604.20006) 将 remembering、reasoning、recommending 和 forgetting-aware FAMA 统一到周/月级长对话评测。本项目使用其当前与失效标准评估生命周期策略。
- [MemoryAgentBench](https://arxiv.org/abs/2507.05257) 将准确检索、测试时学习、长程理解和选择性遗忘区分为不同能力，支持多指标评测设计。
- [MEMPROBE](https://arxiv.org/abs/2606.24595) 直接审计交互后保留的 memory artifact，支持将记忆质量与任务完成结果分别测量。
- [Graphiti](https://github.com/getzep/graphiti) 与 [Zep](https://arxiv.org/abs/2501.13956) 使用有效时间和来源表示时态事实。本项目采用 MemoryCore 上的有界旁路实现。
- [SWE-MeM](https://arxiv.org/abs/2606.28434) 研究代码 Agent 的自适应压缩时机和粒度；D11 验证更窄的证据保真压缩问题。
- [Structurally Aligned Subtask-Level Memory](https://arxiv.org/abs/2602.21611) 指出整实例记忆存在粒度错配；D9--D11 观察到整轨迹结果标签对局部步骤信用不足。
- [ToM-SWE](https://arxiv.org/abs/2510.21903) 研究软件工程交互中的持续用户目标和约束，说明编程迁移需要显式状态与 scope。

本研究位于既有检索引擎与端到端编程 Agent 之间，研究反馈如何提出生命周期候选、下游答案如何执行策略晋升，以及质量、效率和构链证据如何隔离。

## 11. 结论

本项目在 MemoryCore 基座上实现了有界生命周期旁路、策略提出与晋升协议、公开数据适配层、结构化实验输出和精确回退机制，并完成 V1/V2 与 D1--D19 的连续实验。

V1 在 Base 已暴露过时记忆和含遗忘标准的样本上获得答案收益；广覆盖实验未支持全流量默认启用，并发现纯记忆任务的 MPA 伤害信号。V2、多跳、附加槽位、状态投影、过程记忆、前提反驳和立场代理的当前实现均未达到冻结晋升门槛。D11 形成 token 降低 20.84% 且直接证据支持度不变的效率结果。D18 通过纠错事件检测门槛，未通过前驱链接门槛。D19 证明带标签的新旧状态对明确历史/变化问题有显著价值，同时否决了无条件返回和默认替换。

最终策略保留 Base，V1 仅在高置信、scope 一致的纠错关系和经新数据验证的风险条件下进入质量轨；默认只返回 active 后继，明确历史/变化查询可在 `query_aware` 实验路径中获得一组带标签的 superseded/active 状态；D11 进入独立效率非劣验证；自动构链对不确定对象执行 abstain。后续实验应集中于真实编程流量中的查询意图误触发率，以及 repo、branch、commit、worktree 和 environment 范围内的可执行 witness 与精确失效链接。
