# 面向多轮交互式长编程任务的记忆自优化：阶段性调研与实验报告

> 版本：2026-08-24（负责人版）  
> 文档定位：本报告用中文汇总结论、实验结果和决策建议；英文论文 [`paper/main.tex`](paper/main.tex) 保留为理论、方法与完整实验过程的研究产物。  
> 结论边界：公开长对话实验用于验证方法，不等同于真实多轮编程业务效果。

## Executive Summary（执行摘要）

当前研究得到两个可保留结果，但它们解决的是不同目标：

1. **质量方向：V1 是目前唯一获得答案级正向证据的策略。** 在 Memora 冻结的 50 个“基座会暴露过时记忆”问题上，V1 相对 Base 将综合指标 FAMA 从 0.3195 提升到 0.4004，增加 **8.09 个百分点**，95% 置信区间为 **[5.17, 12.59]**；同时 FAA 提升 8.38 个百分点，平均注入 token 仅增加 1.55%。V1 因此保留为研究基准策略，但尚未达到无条件生产推广的证据标准。
2. **效率方向：D11 得到了明确的 token 压缩结果。** 在 LongMemEval-V2 未触碰测试集的 30 个问题上，D11 将平均注入 token 从 2,796.8 降至 2,213.9，减少 **20.84%**；12 个可直接评分问题的答案原子支持度与 Base 完全相同，未出现支持度受损。不过该实验没有生成答案，也没有预先按“非劣质量 + 降本”目标设计，因此只能认定为**成本侧的 Pareto 结果**，不能宣称答案质量等价。
3. **更激进的策略没有得到稳定增益。** V2 虽然提升了检索侧代理指标，但相对 V1 的答案 FAMA 下降 0.43 个百分点、FAA 下降 4.08 个百分点，且 token 增加 37.53%，因此被拒绝。D12、D13 在开发集失败；D14 的结构证据在开发集仅触发 2 次且没有答案收益；D15 在这 2 个开发样例上出现 3/4 读者配对改善，但在新验证集 23 个前提问题上触发数为 0，故在调用答案模型前即被拒绝。
4. **核心方法论结论比单个新策略更稳定。** 记忆自优化必须把“候选提出”和“策略晋升”分开：检索代理改善不能直接代表答案改善；质量优化与效率优化必须使用不同的预注册门槛；失败、超时、关闭开关和结构损坏时必须精确回退 Base。

因此，当前最合理的课题表述不是“已经获得可持续自我进化的通用记忆系统”，而是：**已经实现一套有边界、可关闭、可回退、能从反馈提出候选并用冻结协议拒绝无效候选的记忆自优化框架；其中 V1 有公开长对话答案级收益，D11 有待重新确认的压缩收益。**

## 一、问题定义与方案定位

多轮编程任务中的事实具有生命周期：接口会改名、方案会推翻、依赖版本会切换、用户会撤销先前要求。普通 FTS5 或向量检索可能把“历史上正确”的信息重新注入为“当前事实”。单纯删除旧记忆又可能丢失纠错链，导致系统无法解释当前状态从何而来。

本研究采用 **纠错驱动的记忆失效与版本链**：

- 写入侧识别高置信纠错、撤销和替换事件，建立旧记忆到新记忆的有界前驱—后继关系；
- 查询侧不改写 FTS5、向量索引或抽取模型，而在基座结果之上做最多一跳的重定向、过滤或辅助组织；
- 优化器只能在预先限定的参数和规则空间中提出候选；
- 候选必须依次通过直接证据、答案质量、遗忘安全、token、时延和 fallback 门槛，失败则保留 incumbent；
- 开关关闭、辅助结构异常或超时时，整个调用返回原始 Base 路径。

这一设计主要覆盖题目方向 B（高置信反馈）、C（检索候选与 Top-k）、E（生命周期）和 F（注入预算），同时通过旁路实现满足“不重写基座索引”的约束。

## 二、实验协议与可信度控制

### 2.1 公开数据

| 数据集 | 固定版本 | 用途 | 当前证据边界 |
|---|---|---|---|
| Memora | revision `a6493188efc836d6511ed5e4163fe3ba87da30ff`；600 问题、27,614 会话、10 persona | V1/V2 的检索代理与答案级主实验 | 方法验证；50 个答案问题为 Base 过时暴露条件样本，不代表全部业务流量 |
| LongMemEval-V2 | revision `2cc8c540bdb87fe6761629b585e727e1c4704520`；manifest SHA-256 `70a2be47...fc99a` | D7–D15 的过程/工具轨迹记忆实验 | D11 有未触碰测试结果；D15 只读到验证集，测试集保持未读 |

### 2.2 模型评测

主答案实验使用 **MiniMax-M3** 和 **DeepSeek-V4-Flash** 同时作为读者与裁判。主指标采用交叉裁判：DeepSeek 只评 MiniMax 生成的答案，MiniMax 只评 DeepSeek 生成的答案，排除自评。V1/V2 主面板共执行 300 次读者调用和 600 次裁判调用，重试和返回模型不匹配均为 0；裁判逐标准一致率为 96.79%，Cohen's kappa 为 0.899。

### 2.3 指标

- **MPA（Memory Presence Accuracy）**：回答是否保留当前仍有效、且题目要求使用的记忆。
- **FAA（Forgetting Absence Accuracy）**：回答是否避免使用已经失效的记忆。
- **FAMA**：同时奖励记住有效事实、惩罚复述失效事实的综合指标；是质量方向的主指标。
- **直接支持度**：检索/注入片段是否让参考答案中的原子事实可达；它便宜且确定，但不能替代生成答案评测。
- **代价指标**：平均注入 token、查询和策略选择 p50/p95 时延、回退率及每查询预算违规数。

所有策略使用版本化协议、固定数据切分、机器可读决策和独立重算。开发集只能选方案，验证/测试集只按预先冻结门槛作一次决策；协议改变必须升版本并重跑 Base。

## 三、核心实验结果

### 3.1 V1 获得当前最强的答案级证据

| 指标 | Base | V1 | V2 | V1 − Base（95% CI） | V2 − V1（95% CI） |
|---|---:|---:|---:|---:|---:|
| MPA | 0.3855 | **0.4342** | 0.4461 | **+0.0487** [0.0196, 0.0928] | +0.0119 [-0.0039, 0.0276] |
| FAA | 0.8531 | **0.9369** | 0.8961 | **+0.0838** [0.0599, 0.1067] | **-0.0408** [-0.0762, -0.0064] |
| FAMA | 0.3195 | **0.4004** | 0.3961 | **+0.0809** [0.0517, 0.1259] | -0.0043 [-0.0206, 0.0109] |
| 平均注入 token | 144.52 | 146.76 | 201.84 | +1.55% | +37.53% |

V1 的 FAMA 在 10 个 persona 分组中方向全部为正，说明收益不是由单一 persona 拉动。V2 的检索侧结果更高，却在答案阶段暴露更多过时值并显著降低 FAA。这构成了本课题最重要的反例：**优化检索代理，不等于优化最终回答。**

当前决策：保留 `lifecycle-adaptive-v1.0`，固定参数为 `minConfidence=0.85`、一跳、`k=5`、最多 64 次有界扩展、10 ms 生命周期旁路预算；不推广 V2。

### 3.2 D11 形成独立的压缩收益

| 指标 | Base | D11 | 差值 |
|---|---:|---:|---:|
| 问题数 | 30 | 30 | — |
| 可直接评分问题 | 12 | 12 | — |
| 答案原子支持度 | 0.2083 | 0.2083 | 0 |
| 改善 / 相同 / 受损问题 | — | 0 / 12 / 0 | 无支持度损失 |
| 平均注入 token | 2,796.8 | 2,213.9 | **-582.9（-20.84%）** |
| 查询 p95 | 227.5 ms | 231.1 ms | +3.6 ms |
| 策略选择 p95 | — | 3.08 ms | 有界 |
| token / 证书 / 强制回退违规 | 0 | 0 | 0 |

D11 在 30 个问题中的 19 个执行了证据保真替换。其原冻结目标是“产生质量提升”，由于 12 个评分问题中没有任何一个改善，所以按原协议正确判负；但它在测得的“支持度—token”平面上支配 Base。下一步应在新切分上预先冻结**效率型门槛**，包括答案质量非劣界、最低 token 降幅、时延上限和精确 fallback，再决定是否把它晋升为正式效率策略。

### 3.3 D12–D15 没有产生可晋升的新质量策略

| 方向 | 阶段结果 | 决策 |
|---|---|---|
| D12 轨迹一致的外部证据扩展 | 开发集相对 Base 的直接支持度下降 3.33 个百分点，5 个问题受损；相对 D11 虽有 2 个改善、0 个受损，但置信下界为 0，且因果消融不支持所选规则 | 开发阶段拒绝；验证和测试未读；模型调用 0 |
| D13 残差反馈补丁 | 23 个直接评分问题全部与 Base 相同；补丁使用率 60%，平均 token 增加 0.99%，没有新增可达答案原子 | 开发阶段拒绝；验证、测试和答案面板未读 |
| D14 前提反驳证据 | 33 个前提问题只触发 2 个有效证据，25 个控制问题零误触发；平均 token 仅增加 0.11%。但 4 个变化读者配对全部与 Base 相同 | 因无答案级增益而拒绝；其验证/测试当时保持未读 |
| D15 类型化反驳与充分性契约 | 在 D14 的 2 个已消费开发问题上，4 个读者配对中 3 个改善、1 个相同、0 个受损；但新验证集 23 个前提问题触发数为 0，20 个控制问题也为 0，43 个上下文全部与 Base 精确一致 | 因验证覆盖率为 0 拒绝；答案调用 0、裁判调用 0；测试保持未读 |

D15 的失败不是模型或余额问题，而是其前置结构触发器未能跨切分复现。独立验证对 16 项完整性检查全部通过、重算不一致数为 0；唯一失败项就是协议要求的有效触发数。因此，开发集上的 3/4 改善只能作为机制线索，不能作为有效性结论。

## 四、D1–D15 方向总览

| 类别 | 方向 | 当前状态 | 保留价值 |
|---|---|---|---|
| 生命周期质量主线 | V1 纠错链重定向 | **保留为 incumbent** | 唯一通过当前答案级证据的质量策略 |
| 更大检索预算 | V2 | 拒绝 | 证明代理提升可能损害遗忘安全并增加成本 |
| D1–D2 渲染屏蔽与风险路由 | D1、D2 | 答案门槛拒绝 | 揭示“删除过时词”也可能破坏恢复有效事实所需的实体锚点 |
| D3–D6 有效状态筛选、装箱与组合 | D3、D4、D5 拒绝；D6 仅后验安全可行 | 未晋升 | D4 是近失方向；D6 仍需新的确认边界，不能沿用已消费数据晋升 |
| D7–D10 轨迹变化与过程记忆 | D7–D10 拒绝 | 未晋升 | 证明轨迹级成功反馈过粗，局部替换还可能丢失正文答案证据 |
| D11 证据保真压缩 | 质量门槛拒绝；**保留效率结果** | 待新效率协议确认 | 当前最明确的 token 降本方向 |
| D12–D13 外部证据与残差补丁 | 开发集拒绝 | 停止 | 安全、可审计并不自动产生答案可用性 |
| D14–D15 前提反驳与类型化契约 | D14 答案拒绝；D15 验证拒绝 | 停止当前触发器 | 类型化提示在极小开发样例有效，但结构覆盖不能泛化 |

这些方向并非“全部无用”。负结果已经缩小了可行空间：继续增加 Top-k、堆更多证据或只优化直接支持度的边际价值很低；更值得投入的是**质量与效率分轨晋升、面向编程范围的纠错事件建模，以及覆盖率先行的结构触发诊断**。

## 五、当前可以与不可以得出的结论

### 可以得出

- 纠错链 + 有界查询重定向能在公开长对话的过时记忆问题上改善答案级 FAMA，V1 是当前证据最充分的实现。
- 检索代理与生成答案之间存在可复现的排序反转，必须保留答案级晋升门槛。
- D11 能在当前直接支持度定义下显著减少注入 token，且没有观测到支持度、证书或 fallback 违规。
- 冻结协议能有效阻止开发集偶然提升被错误晋升；D15 是一个明确例子。
- 旁路策略可关闭，故障时可硬回退 Base，不需要替换 FTS5、向量索引或抽取模型。

### 不能得出

- 不能宣称这些结果已经在真实多轮编程任务、代码仓库操作或内部用户流量上成立。
- 不能把 D11 的直接支持度持平表述为生成答案质量非劣。
- 不能把 D15 的开发集 3/4 改善表述为策略有效；新验证集没有触发覆盖。
- 不能把两位模型的一致性当作人工裁判或更广模型总体的完全替代。
- 不能把 V1 直接作为无条件生产默认策略；它仍需内部编程数据的范围、分支、环境与工具状态适配验证。

## 六、建议的下一阶段计划

1. **优先确认 D11 的效率价值。** 新建一次独立、未读切分，预先声明“答案质量非劣 + token 至少下降 + 时延/回退合格”的效率协议；补充答案生成，不再只看直接支持度。
2. **把 V1 接入小规模内部编程试点。** 数据适配层至少要提供 `conversation_id`、`turn_index`、时间、scope、记忆候选、纠错关系和任务结果；scope 需覆盖仓库、分支、工作树、环境、文件/符号和任务阶段。
3. **先测触发覆盖，再花费模型调用。** 对新结构策略设置最低覆盖率和控制集误触发门槛；覆盖不过关时像 D15 一样直接停止，节省读者/裁判成本。
4. **分开维护质量策略与效率策略。** V1 作为质量 incumbent；D11 类候选只在效率轨道竞争。两类策略使用不同的目标函数和晋升规则，避免事后改口径。
5. **建立内部编程错误标签。** 优先标注高置信显式纠错、约束重述、撤销/回滚、接口更名和环境切换；任务失败只能作为弱信号，不能单独触发记忆失效。

建议下一阶段的最小成功标准是：在内部小规模、人工可复核的多轮编程会话上，V1 相对 Base 的当前约束正确率和过时约束抑制率均不下降；D11 效率候选在答案质量非劣的前提下降低至少一个预先声明的 token 比例；所有关闭、损坏和超时用例与 Base 精确等价。

## 七、开放问题与风险

- 公开长对话中的“persona 事实变更”与编程中的“分支局部事实、代码移动、隐式废弃”并不完全同构。
- 当前纠错链主要依赖可识别的显式替换；对不重复旧值的隐式纠错、跨文件影响和多分支并存仍缺乏证据。
- 50 个答案问题是条件样本；D11 只有 12 个直接评分问题；D14/D15 的可触发样本更少，统计外推必须保守。
- 使用模型裁判降低了人工成本，但仍可能共享偏差；内部试点应抽样人工复核高影响错误。
- 协议在仓库内版本化并可复算，但不是外部时间戳预注册。
