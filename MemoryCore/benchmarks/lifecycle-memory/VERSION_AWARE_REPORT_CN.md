# 版本/分支感知的多状态记忆闭环

**TencentDB Agent Memory 实现与真实评测**
交付日期：2026-08-31　分支：`codex/version-aware-multistate-memory`　评分前提交：`4d77e6984f81`

## 结论

建议采用版本感知多状态记忆，并以灰度开关上线。它把“旧/当前”这一条线性链升级为仓库、分支、worktree、并行任务四级有效域：普通执行只返回当前域内有效状态；比较、迁移、回归或历史问题才返回同仓库、带来源标签的多个状态；缺少仓库上下文时拒绝注入有作用域的记忆。

真实答案评测中，版本能力 criterion accuracy 达到 **100.00%**：相比全局混合召回的 94.29% 提升 **5.71 个百分点**（95% 区间 [2.86, 8.57]），相比把并行状态误建成线性新旧链的 67.50% 提升 **32.50 点**（[30.36, 34.64]）。更显著的收益发生在回答之前：期望状态精确选择率由两组基线的 0% 提升到 **100%**，跨状态污染率由 100% 降到 **0%**，能力面板平均注入 token 相比分别减少 **29.04%** 和 **18.80%**。

这不是“所有问题都大幅涨分”。全局混合召回已经能凭记忆正文中的所有权描述答对多数简单题，因此分支、worktree、任务当前态和跨分支比较的答案分数与它持平；新方案的直接答案增益主要来自无上下文时不乱猜。它的核心价值是把提示上下文从“模型也许能辨别的混合状态”变成“系统已验证的有效状态”，降低复杂真实任务中的状态污染风险。

## 1. 方案与闭环

每条 L1 记忆附带结构化有效域：`repositoryId`、`branch`、`commitSha`、`worktreeId`、`taskId`、`scopeLevel`。仓库和 worktree 标识由真实 Git 信息计算为不可逆短哈希，不持久化本地路径或远端 URL。提交号用于溯源；有效性按作用域判断，兄弟分支、不同 worktree 和并行任务可以同时存在，不互相覆盖。

写入闭环如下：宿主在 capture 时传入 `workspaceDir`、`taskId` 或显式 `versionContext`；Git 探测器生成坐标并按“会话 + 任务”保存，异步 L0→L1 管线继续携带同一坐标。去重和 update/merge 只查看完全相同的有效域；只有旧 ID 全部在该域内核验且新记录可查询后，才发布同域纠错边。兄弟状态不会被删除，也不会被错误连成前驱—后继。

召回闭环如下：MemoryCore 先从真实 L1 检索中多取候选，再解析可信纠错边，最后执行版本选择。普通问题按 task → worktree → branch → repository 的有效性筛选并标记 `ACTIVE SCOPE`；明确比较、迁移、回归和历史问题返回同仓库的有界多状态，并标记分支、提交、worktree、任务及 `active_here`；没有仓库上下文时，有作用域记忆全部弃权，旧的无作用域数据仍沿用兼容路径。线上记录选择模式、抑制数量、标签数量、当前状态数、回退和延迟；离线 Reader/Judge 或人工反馈用于决定策略是否晋升，不自动跨域改写记忆。

核心接入位置：

| 环节 | 代码位置 | 作用 |
|---|---|---|
| 有效域模型与选择 | `src/core/lifecycle/version-scope.ts` | 有效性、查询意图、标签、多状态选择 |
| Git/worktree 探测 | `src/core/lifecycle/git-context.ts` | 同仓库身份、不同 worktree 身份、隐私哈希 |
| 异步上下文延续 | `version-context-store.ts`、`pipeline-factory.ts` | 同会话并行任务不串域 |
| 写入与去重 | `l1-dedup.ts`、`l1-writer.ts` | 只在相同有效域更新、删除和建边 |
| 最终生产召回 | `auto-recall.ts` | 真实 ID 候选、过取、筛选、标签、最终提示 |
| 宿主入口 | `tdai-core.ts`、`index.ts`、`gateway/*` | OpenClaw 与 Gateway 显式或自动传入上下文 |

建议配置：

```json
{
  "recall": {
    "lifecycle": {
      "enabled": true,
      "versionAwareMode": "strict",
      "autoDetectGit": true,
      "versionCandidateMultiplier": 4,
      "maxVersionStates": 6
    }
  }
}
```

自动探测采用保守的 worktree 级作用域；并行任务应传稳定 `taskId`；确实要跨 worktree 共享的分支级事实，应由宿主显式传入 `scopeLevel: "branch"`。

## 2. 冻结实验

实验在看答案前固定协议、上下文哈希和门槛。能力面板为 10 组编程状态 × 7 类问题，共 70 题：分支当前态、worktree 当前态、同 worktree 并行任务、分支比较、迁移、回归、缺失 scope 弃权。每组状态写入真实临时 Git 仓库的 main、release、两个 detached worktree 和两个并行任务；使用真实 SQLite/FTS5、`writeMemory` 和 `performAutoRecall`，不使用手工排序的内存检索器。

安全面板取固定 Memora 提交 `a6493188…` 的周级公开数据，从 10 个 persona 各按字典序冻结 4 题，共 40 题。三组方案对这些旧式无作用域记忆生成逐字节相同提示，只检验向后兼容是否退化。它不是新的外部留出集。

三组方案为全局混合召回、线性新旧双态、版本感知多状态。共执行 50 个真实 SQLite 数据库、260 次 `writeMemory`、330 次最终生产召回；110 题 × 3 组形成 330 个题组上下文，逐字节去重后每个 Reader 为 250 个提示。MiniMax-M3 与 deepseek-v4-flash 都作为 Reader，并由另一模型交叉 Judge：**500 次真实 Reader 调用 + 500 次 Judge 调用**，无自评。

主指标是能力题 criterion accuracy；安全指标是 Memora FAMA；上下文指标为期望集合精确率、期望状态召回率和污染率。95% 区间按场景/persona 做 5,000 次配对聚类 bootstrap。评分提交为 `4d77e698…`，上下文 SHA-256 为 `2c64c12d…a1960f`，原始评测 SHA-256 为 `e546f4f9…65ee61`。

## 4. 判断与边界

实验支持把版本感知多状态作为线性新旧双态的升级：后者把“同时正确”误当成“旧值被新值取代”，在 worktree 和并行任务当前态上分别损失 50 点；新方案把线性更新保留为同一有效域内的一种关系，同时允许多个域并存。全局混合召回在简单题上仍很强，但把 100% 的问题上下文都暴露给无关状态；随着真实任务状态更长、所有权描述更弱或模型更小，这种依赖模型自行消歧的风险会增大。

本次已证明真实 Git/worktree 探测、真实 SQLite 写入、生产召回、最终提示和真实双模型答案链路有效；未证明自动 LLM 抽取能总是选对 `scopeLevel`，也未测在线 TCVDB/COS 网络延迟、分支重命名与复杂 merge ancestry、无控制真实编程流量中的冲突发生率或人类裁判一致性。上线应先开启影子指标，再按仓库灰度；跨域泄漏、错误删除兄弟状态或缺失上下文仍返回 scoped 记忆，任一出现都应立即回退。
